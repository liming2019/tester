# Verify Db Sync Result

这个 skill 只用于“核验已有同步结果”，不负责执行写库同步。

## 核验前确认

在正式核验前，必须先和用户确认数值比较规则：

1. 金额字段是否允许四舍五入
2. 如果允许，保留几位小数
3. 比率字段是否也按同样规则处理

用户未确认前，可以先做结构探查，但不要给出最终通过或不通过结论。

默认先问：
`金额字段是否允许四舍五入？如果允许，请告知保留几位小数；比率字段是否也按同样规则处理？`

## 核验流程

按下面顺序执行，不要跳步：

1. 读取源表和目标表结构
2. 根据字段注释和字段名建立映射
3. 确认业务键或唯一记录定位方式
4. 先核验总条数
5. 再按业务键逐条核验
6. 汇总差异并分析原因
7. 生成中文 HTML 报告
8. 交付前检查乱码

## 业务键规则

优先级如下：

1. 表真实主键
2. 唯一索引
3. 业务唯一键组合

如果表没有真实主键，必须使用可唯一定位记录的业务键，并在报告中明确写出。

例如：

- `date + advertiser_id + video_id`
- `sync_date + sync_type + advertiser_id`
- `stat_date + advertiser_id + material_id`

## 字段映射规则

字段映射必须优先使用字段注释语义，而不是只按字段名硬匹配。

映射顺序：

1. 用户明确指定的映射
2. 字段注释语义匹配
3. 字段名匹配
4. 标记为未映射

如果映射关系本身有歧义，必须在报告里写明。

## 总条数核验

总条数核验至少包括：

1. 源表总条数
2. 目标表总条数
3. 源表唯一记录数
4. 目标表唯一记录数

如果用户指定日期或范围，只能在该过滤范围内统计。

## 逐条字段核验

逐条核验时，必须检查每条记录中每个映射字段的值是否一致。

差异至少分为：

1. 源表有、目标表无
2. 目标表有、源表无
3. 字段值不一致
4. 字段映射或展示字段不一致

## 差异展示规则

发现差异时，报告主体必须使用表格展示，不能只给 JSON。

差异表格必须至少包含：

- 业务主键
- 源表主键字段
- 目标表主键字段
- 差异字段
- 源值
- 目标值
- 差异说明

约束如下：

1. 业务主键只展示一列，不要重复展示两列一模一样的业务主键
2. 如果源表没有自增主键，可以用“业务键”作为源表主键字段内容
3. 如果目标表有自增主键，必须输出目标表主键 ID；如果没有，则用业务键代替并在列名中写清楚
4. 差异表不要全量平铺所有记录，必须按“差异字段”分组展示
5. 每个差异字段只举 1 到 3 个样例，不要全部显示

## 概述展示规则

报告中的“概述/总结”部分必须先给出：

1. 核对结论摘要
2. 差异字段汇总

推荐格式：

`概述：总结核对结果，如差异字段有 A、B、C，以下为部分数据说明（每个差异字段举例 1-3 个，不用全部显示）`

## 样例要求

如果存在源表有、目标表无：

- 必须举例
- 必须带业务主键
- 必须带源表主键字段
- 必须带目标表主键字段，若不存在则留空

如果存在目标表有、源表无：

- 同样必须举例
- 必须带业务主键
- 必须带源表主键字段，若不存在则留空
- 必须带目标表主键字段

如果存在字段值差异或字段映射差异：

- 必须按差异字段分组
- 每个差异字段举例 1 到 3 个
- 不要把全部差异记录原样堆到报告里

## 报告要求

必须输出一份中文 HTML 报告，内容至少包括：

1. 核验范围
2. 核验时间
3. 源表 / 目标表
4. 业务键说明
5. 字段映射说明
6. 总条数核验结果
7. 源有目标无差异表
8. 目标有源无差异表
9. 字段值差异表
10. 字段映射差异表
11. 概述 / 总结
12. 结论
13. 失败原因总结

## 明细显示规则

如果某个核验项完全无差异：

- 不要显示该项的明细部分
- 只在汇总表中保留该项结果

## 乱码检查

HTML 生成后，必须再次读取报告文件，检查：

- 标题是否正常中文
- 表头是否正常中文
- 正文是否正常中文
- 差异字段名称是否正常中文

如果存在乱码、`????`、编码污染，必须先修复再交付。

## 失败原因总结

核验失败时，至少从下面角度归因：

1. 目标表未同步或补数未完成
2. 业务键映射错误
3. `-1/-2/NULL` 等特殊值映射不一致
4. 金额或比率字段精度、舍入规则不同
5. 聚合口径不同
6. 目标字段取错来源字段
7. 展示字段与业务字段混用

## 交付格式

最终回复用户时，至少提供：

1. 简短结论
2. HTML 报告路径
3. 是否按四舍五入口径判定通过
4. 是否存在必须开发修复的问题
