# 报告生成与交付门禁

## 主报告结构

- 主报告只展示摘要、核心统计、结论和风险。
- 执行明细、缺陷明细、接口明细、性能明细、SQL 核验明细必须独立输出。
- 多接口、多页面或 suite 批次入口必须使用公共报告模板；禁止手工拼接简化 HTML 作为正式批次入口。

## 详情归属

- 多接口、多页面或多测试项报告交付前必须做详情归属检查。
- 报告级“查看详情”必须进入当前测试项对应的独立明细报告。
- 明细页正文不得混入其他接口、页面、表名、数据源证据、业务键、阻塞项或结论。

## 统计边界

- 主报告汇总页只展示核心测试项统计和核心风险。
- 前置、契约、数据准备、诊断项不得计入核心通过率。
- 当核心通过但全量存在 FAIL/WARN/BLOCKED 时，主报告和最终回复必须说明影响范围。

## 自审门禁

生成或更新测试报告后，必须先读取最终 HTML/Markdown/JSON/报告索引产物做自审。

自审至少覆盖：

- 结论与全量统计一致。
- 核心、辅助、前置、调试项边界清晰。
- FAIL/WARN/BLOCKED 均有影响说明。
- 覆盖缺口和样本限制明确。
- 同一证据不重复堆砌。
- 敏感信息已脱敏。
- 用户历史反馈已回归。
- 正式报告包通过 `automation/validate_report_package.py`。

若自审发现 P0/P1 问题，禁止把报告标记为最终交付。

## 正式包体积与证据归档

- `reports/final/` 只保存可直接评审的轻量正式包，不保存普通运行流水和未被正式报告引用的重复产物。
- 正式报告包目录名必须使用 ASCII slug，不得包含中文、空格或 Windows 保留字符。
- 单个正式报告包 Git 纳管软上限为 10 MB，硬上限为 20 MB。
- 单文件软上限为 2 MB，硬上限为 5 MB。
- `evidence/` 下 JSON 合计软上限为 3 MB，硬上限为 8 MB。
- 正式包必须在 `manifest.yaml` 中声明 `artifact_policy`，至少包含 Git 包体积上限、单文件上限、JSON 证据上限和归档策略。
- 完整逐项 JSON 默认归档到来源 `RUN-*` 或外部制品包；Git 中优先保留汇总 JSON、证据索引、来源路径、SHA256 和复核方式。
- 剥离 HTML/JSON 前必须完成链接有效性检查；任何 `href` 指向不存在文件时，正式包门禁必须失败。
