# 自动化资产与执行治理

## 资产分层

- `automation/` 存放可复用自动化资产、公共报告模板、执行器、接口元数据和 suite。
- 单次任务生成的临时脚本、调试缓存、原始响应和运行日志默认进入 `work/versions/<VERSION-ID>/runs/<RUN-ID>/`。
- 自动化资产变更必须说明输入材料、适用范围、执行方式和验证结果。

## 执行前门禁

- 执行自动化前必须确认环境、账号、权限、测试数据、只读/写入边界和依赖可用。
- 已存在矩阵、suite 或执行器时，正式执行应优先复用，不得为单一接口或页面重复复制完整框架。
- 生产、预发环境默认只读；压测和写入必须有明确授权、停止条件和回滚方案。

## 报告生成

- 自动化执行结果必须进入公共报告生成链路或已确认报告模板。
- 不得把临时 HTML 拼接结果作为正式报告。
- 报告生成后必须运行报告包门禁和自审。

## 缓存与敏感证据

- 原始响应、token、cookie、私钥、密钥、连接串、截图和 HAR 默认视为敏感证据。
- 敏感证据必须存放在 `work/sensitive/`、来源 `RUN-*` 受控目录或用户指定受限目录。
- 敏感证据不进入正式报告、不写入 Git 纳管索引、不提交 Git。

## 二进制依赖

- 必须纳管的二进制依赖应记录版本、来源、SHA256、用途和替换规则。
- 不再使用的二进制依赖必须清理或归档；不得长期堆积多个版本。
