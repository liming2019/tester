# 提取功能测试点

从原型、截图、需求文档、备注、控件说明、变更说明、弹窗截图、局部截图，或结构化需求数据中，提取可直接用于评审的功能测试点清单。

## 最高优先级强制约束

1. 本技能执行顺序严格固定，禁止调换、跳过、后置补全，所有步骤必须按顺序完成。
2. 判定标准：先完成规范测试点纯文本（`plaintext`）→ 校验格式、层级、内容合规 → 最后才允许转换生成 XMind 文件。
3. 红线规则：
   - 未输出合规 `plaintext` 测试点文本前，严禁生成、提及、制作 XMind 产物。
   - 不允许“先出 XMind 再补测试点/修正格式”，该行为判定为违规执行。
   - 格式、层级、内容不符合挂载规则时，立即停步修正，不进入下一环节。

## 标准执行步骤（强制顺序）

Step1：依据需求提取测试点，严格遵循挂载规则，输出纯文本格式测试点。  
Step2：自检：层级缩进、内容范围、逻辑完整性，确认 `plaintext` 完全合规。  
Step3：仅当前两步全部完成并自检通过后，执行 XMind 转换与产出。

## 执行收尾要求

输出末尾必须固定添加自检声明：

`✅ 已按顺序执行：纯文本测试点提取 → 格式校验 → XMind生成，全程未调换流程`

## 输入路径

这个 skill 现在支持两条输入路径：

1. 视觉/文档输入
   - 页面原型
   - 整页截图
   - 局部截图
   - 备注图
   - 变更说明
   - 需求文档
2. 结构化需求输入
   - 来自 `$lanhu-requirements-extractor` 的页面级需求输出
   - 常见字段包括：
     - `page_name`
     - `prototype_structured`
     - `canvas_annotations`
     - `canvas_text_notes`
     - `interaction_states`
     - `right_panel_notes`

当输入是第二种时，不要再按“看图识别”的思路工作，而是把结构化字段当作已经挂载好的需求来源继续整理测试点。
当输入来自 `lanhu-requirements-extractor` 时，默认按“页面级需求摘要 -> 页面级测试点”输出，不要退化成碎片化控件识别清单。

## 工作流

1. 先确定输出范围。
   - 整页原型或整页截图：按页面级输出。
   - 用户明确只看某个模块：从该模块开始输出，不补页面名、父模块或同级模块。
   - 按钮、弹窗、抽屉、下拉框、表格局部图：只输出其所属模块，不扩展整页。
   - 无额外说明时，默认补充功能权限测试点：新功能页面需求，默认提取页面内操作按钮的功能权限测试点；迭代需求，只对本次迭代相关部分补充功能权限测试点，不扩展存量功能。
2. 先做信息挂载，再写测试点。
   - 同一页面的整页图、局部图、弹窗图、备注图、版本说明，先挂到真实入口点或真实模块下。
   - 局部图是某个按钮、链接、操作项的补充时，挂在该入口点下，不新建平级顶层模块。
   - 编号备注、控件说明、页面 notes、widget notes，优先挂到同编号或同位置控件下。
   - 遇到筛选项、表单项、下拉项、时间项时，先提取并挂载：名称、控件类型、取值范围、默认值、独立规则、依赖关系、联动校验，再组织成测试点。
   - 如果输入来自 `lanhu-requirements-extractor`，按以下优先顺序挂载：
     - `prototype_structured`：挂到页面级模块或版本变更点下
     - `canvas_annotations`：优先挂到对应字段、控件、操作项或列表列名下，作为该字段测试点的子点
     - `canvas_text_notes`：优先挂到对应字段、控件或模块下，作为字段补充说明、提示文案或业务规则子点
     - `interaction_states`：挂到触发它的按钮、链接、Tab、列表操作项或热点入口下
     - `right_panel_notes`：作为字段级规则补充挂载
3. 按优先级消解冲突。
   - 补充说明或用户新要求 > 备注或控件说明 > 局部图或弹窗图 > 整页静态原型。
   - 高优先级已覆盖的内容，低优先级表述不重复输出。
4. 只保留材料明确支持的内容。
   - 可以输出：功能、字段、控件约束、联动、状态、展示、排序、回显、维护边界、已删除、已隐藏、暂不处理、功能权限测试点。
   - 不输出：材料未明确的接口规则、性能、安全、兼容性、错误码、后端逻辑、状态流转。
   - 功能权限测试点按默认规则补充；如用户额外指定只看某一模块或某一迭代范围，则权限点也只落在该范围内。
   - 对“测试经验补充”与“需求明确支持”必须区分处理：
     - 需求、原型、注释、说明、弹窗截图明确支持的内容，按正式测试点输出。
     - 基于测试经验补充、但材料未明确支持的内容，不得直接伪装成需求事实；应标记为“待确认”或“测试补充”，除非用户明确要求直接纳入正式测试点。
5. 回答前去重压缩。
   - 删除重复模块、重复入口点、重复规则。
   - 能直接表达清楚时，不补“查询规则”“展示规则”“保存规则”这类空壳层。
6. 优先生成“可评审测试资产”，不是“需求复述稿”。
   - 输出目标是测试评审脑图/测试点评审清单，而不是页面说明摘要。
   - 不要停留在“支持某功能”“存在某按钮”层面；应尽量下沉到可验证场景、字段规则、统计口径、联动口径、分页/筛选/重置/导出等测试对象层。

## 专项参考

只有命中对应场景时，才读取专项参考，避免普通页面测试点提取加载过多上下文：

- 第三方单据、目标业务单据、外部系统单据、同步单据、推送单据、发放单、领用单、采购单、订单、工单、凭证、字段映射表等场景：读取 `references/target-document-field-mapping-testpoints.md`。

## 当输入是结构化需求时的处理规则

如果输入已经是页面级结构化需求，不要重新发明页面结构，按下面规则整理：

- `prototype_structured`
  - 识别页面目的、模块定位、权限要求、版本变更点
  - 如果是“版本 / 版本内容 / 说明”格式，优先挂到真实模块，不单独保留“版本说明”模块；除非用户明确要求按版本整理
- `canvas_annotations`
  - 视为字段级强说明
  - 优先用于补字段语义、默认值、展示规则、联动规则
  - 不要输出独立的“画布内注释”模块；定位到字段、控件、操作项或列表列名时，必须内嵌到对应测试点下面
- `canvas_text_notes`
  - 视为页面内直接可见规则
  - 常用于提示文案、规则阈值、定义条件、业务约束
  - 不要输出独立的“画布内说明文案”模块；能对应到字段、控件、操作项或列表列名时，必须内嵌到对应测试点下面
- `interaction_states`
  - 视为入口触发后的交互内容
  - 必须挂到触发它的按钮、链接、Tab、列表操作项或热点入口下
  - 如果 `result_type` 是 `modal`、`drawer`、`popover`、`panel_state` 或 `secondary_page`，优先按“打开/显示结果 -> 标题 -> 字段 -> 操作 -> 说明”的顺序收敛
  - 弹窗、抽屉或二级页中的字段说明、画布注释和提示文案，继续挂到该交互态内部字段下
  - 不要把交互态内容拆成无来源的顶层“弹窗”模块
- `right_panel_notes`
  - 视为字段级或控件级补充说明
  - 如果其中的 `元素/字段` 仍是通用控件名，如 `(下拉列表)`、`(文本框)`，应优先结合页面已有业务字段语义改写成真实字段名后再整理测试点

当四类来源中出现重复内容时：

- 优先保留语义最具体的一条
- 优先级一般为：
  - `canvas_annotations` / `canvas_text_notes`
  - `right_panel_notes`
  - `prototype_structured`

额外要求：

- 页面名必须保留
- 模块名如果上游已给出，必须保留
- 同一页面内的测试点应先按页面级模块输出，再向下展开
- 不要把多个页面的规则混成一个总模块

## 交互态内容挂载规则

当输入包含 `interaction_states` 时，先按 `trigger` 找到真实入口，再把交互后的内容收纳到该入口下。

推荐写法：

```plaintext
操作按钮
	新增爆品
		点击后显示从原型实际提取到的新增弹窗
			弹窗标题：使用原型实际标题
			弹窗字段
				字段名A：仅输出原型明确给出的字段规则、默认值、必填、选项、联动或说明
				字段名B：仅输出原型明确给出的字段规则、默认值、必填、选项、联动或说明
			弹窗操作
				操作按钮名A：仅输出原型明确支持的操作结果
				操作按钮名B：仅输出原型明确支持的操作结果
```

如果入口在列表操作列中，则挂到列表操作项下：

```plaintext
列表
	操作列
		编辑
			点击后显示编辑弹窗
```

不要输出成：

```plaintext
弹窗
	新增爆品设置
```

也不要输出“按弹窗要求填写”“按页面要求选择”“正常填写”“正常提交”这类空泛话术。字段只有名称、没有规则时，只保留字段存在性；字段规则、必填、默认值、选项、联动、提交结果必须来自原型、注释、说明或用户补充材料。

## 画布说明和注释的字段级挂载规则

当 `canvas_annotations` 或 `canvas_text_notes` 能定位到真实字段、控件、操作项、列表列名、筛选项、按钮或弹窗字段时，必须挂到该对象已有测试点下面，不单独新增同级模块。

定位优先级：

- 明确字段名、标签名、列名或按钮名完全匹配时，挂到该字段或操作项下。
- 说明文案紧邻某个字段或列名时，挂到该字段或列名下。
- 注释编号能对应到页面上的控件位置时，先用该位置推断真实业务字段名，再挂载。
- 如果只能定位到模块，不能定位到具体字段，则挂到该模块下作为模块级规则。
- 只有完全无法定位时，才允许输出“未定位补充说明”一类兜底节点，并在同一页面内尽量避免使用。

列表字段的推荐写法：

```plaintext
列表
	字段展示正确
		内容区：展示成片/素材
		一级类目：展示所属一级类目
		二级类目：展示所属二级类目
		爆品值：展示当前分类对应爆品值
			爆品值说明展示正确：展示“该分类下的视频累计消耗到此值后将会被定义为爆品”
		创建时间：展示新建成功时间
			创建时间说明正确：创建时间表示新建成功的时间
		创建人：展示创建人信息
		操作：展示编辑、删除操作
```

不要输出成：

```plaintext
画布内说明文案
	爆品值说明展示正确：...
画布内注释
	创建时间说明正确：...
```

## 推荐的结构化输入模板

如果上游把页面摘要整理成下面格式，这个 skill 应直接消费：

```text
页面：爆品设置V1.4.6
模块：内容管理 / 爆品设置

一、原型正文说明
- V1.4.6 / 爆品设置 / 不同分类进行不同消耗的爆品值定义，可以批量设置，列表显示独立
- V1.4.6 / 权限 / 添加爆品设置菜单权限；新增、编辑和删除权限

二、画布内注释
- A1 / 名称 / 一开始没有，根据后台分销等级设定后显示

三、画布内说明文案
- 爆品值 / 该分类下的视频累计消耗到此值后将会被定义为爆品

四、右侧页面说明
- 创建时间 / 新建成功的时间
```

这个 skill 在看到这种输入时，应直接进入“挂载 -> 去重 -> 生成测试点”流程，不需要再把它还原成图片理解任务。

## 默认输出粒度

当输入来自 `lanhu-requirements-extractor` 时，默认输出粒度为：

- 页面
- 页面下的真实模块
- 模块下的功能测试点

优先输出“测试设计骨架”，而不是只按需求来源归类。默认应尽量组织成：

- 页面进入
- 权限限制正确
- 列表筛选 / 筛选区
- 列表展示 / 统计区
- 操作按钮
- 弹窗 / 抽屉 / 二级页
- 分页
- 导出
- 图表 / 趋势图 / 维度切换

当页面明显属于列表管理页、配置页、分析页时，应优先套用对应测试骨架，再将需求细节挂入骨架下。

不要优先输出这种过碎结构：

- 单个控件孤立成顶层
- 通用控件名堆叠
- 与业务语义脱节的截图识别结果

更优先的输出方向是：

- 页面名称
- 模块
- 筛选、列表、操作、弹窗、权限、导出、跳转等真实功能点
- 单筛选项 / 组合筛选 / 分页后筛选 / 重置
- 字段展示 / 字段口径 / 去重口径 / 默认值 / 边界规则
- 维度切换 / 图表切换 / 指标切换后的结果正确

## 输出要求

1. 整个结果放在一个 markdown `plaintext` 代码块中。
2. 只输出测试点，不写分析、说明、总结、建议。
3. 页面名和模块名顶格写。
4. 所有下级层级一律使用 Tab 缩进，不用空格。
5. 层级按真实模块自然展开，不为凑结构补中间层。
6. 表述简洁，贴近人工评审清单。

示例：

```plaintext
页面名称
模块
	功能点
		子点
```

## XMind 辅助输出

默认输出仍然是 markdown `plaintext` 代码块。只有用户明确要求输出 XMind、`.xmind`、脑图，或把测试点转成 XMind 时，才生成 XMind 文件。

XMind 是测试点的导出格式，不是重新生成测试点的入口。必须先产出一份符合本 skill “输出要求”和“最终检查”的 `plaintext` 测试点，再由这份 `plaintext` 按 Tab 层级机械转换成 XMind。

禁止事项：

- 禁止跳过 `plaintext` 测试点，直接手写或硬编码 XMind 树。
- 禁止在 XMind 转换阶段新增、删除、改写测试点。
- 禁止把 XMind 包结构校验当成内容校验。
- 禁止为了补齐脑图层级加入材料未明确支持的测试点。

生成规则：

- 根节点使用项目名、版本号和“测试点”，例如 `云视频1.4.6测试点`
- 第二层优先使用页面名
- 第三层使用模块名
- 后续层级按 `plaintext` 测试点的 Tab 层级展开
- 不新增 `plaintext` 中不存在的测试点
- 文件命名遵循上游业务域规则，例如 `ysp_1.4.6_test_points.xmind`

转换前必须校验 `plaintext`：

- 已通过“最终检查”中的所有内容规则。
- 没有材料不支持的通用 CRUD 推断，例如未明确时不写新增成功、编辑成功、删除成功后的数据变化。
- 没有未真实提取的交互态，例如未抓到弹窗时不展开弹窗标题、字段和按钮。
- 画布说明、画布注释、交互态内容都已挂到正确字段或入口下。
- 权限点已挂到真实操作入口；如果材料或默认规则要求接口鉴权，接口鉴权层也已体现。

交付前必须校验：

- XMind 内容与已校验的 `plaintext` 测试点一致。
- 目标 `.xmind` 文件真实存在
- 文件路径是本地绝对路径
- zip 包内 `content.json` 或等效内容文件存在
- 包内中文没有变成 `???`、乱码或问号占位
- 如果使用模板生成，不能留下重复的 `content.json` 条目

如果最终交付包含 XMind，则回答中必须同时提供：

- `plaintext` 测试点源文件的本地绝对路径
- `.xmind` 文件的本地绝对路径

禁止只交付 `.xmind` 文件而不交付对应的 `plaintext` 源文件路径。

如果无法确认 XMind 文件可用，不要声称已完成；应说明当前卡在哪个校验项。

## 组织规则

- 只按真实页面结构拆分，如 Tab、筛选区、操作按钮区、列表、分页、导航链接。
- 同一模块来自多张图时，合并输出，不重复起模块。
- 一个功能点下如果同时包含控件属性、联动、多选、回显、维护边界，放在同一功能点下表达，不要过度拆散。
- 同一功能点下如果存在多个并列子对象、子字段或子筛选项，保留父项，再向下拆分子点表达；不要把多个子点用分号并排压缩在同一行。
- 同一对象的属性信息，如单选/多选、默认值、候选项、排序方式、提示文案、前后包含等，能够在一条内表达清楚时，合并为同一测试点，不机械拆成多条。
- 如果材料明确标注“已删除”“已隐藏”“暂不处理”，要原样体现在测试点中。
- 如果材料是版本变更说明，变更点应合并进对应真实模块，不单独生成“版本说明”模块；除非用户明确要求按版本整理。

## 常见模块写法

### 筛选区

- 列表页中的筛选模块，优先命名为“列表筛选”；只有明显不是列表筛选区时，才继续使用“筛选区”。
- 画布上可见的筛选项必须逐项盘点并输出，即使没有右侧说明、画布注释或额外备注，也不能漏掉。
- 优先按“单筛选项筛选正确 / 组合筛选 / 切换页码后筛选 / 重置”这一组结构收敛表达。
- “单筛选项筛选正确”下再展开各筛选项的属性、取值、匹配方式、是否单选或多选。
- 筛选项只有字段名或 placeholder、没有明确规则时，至少输出“字段名筛选：支持按该字段筛选，筛选结果正确”；不要因为没有详细说明就省略该筛选项。
- 单个筛选项如果同时包含作者、团队、分组、时间类型、数值条件等多个并列子项，先写父筛选项名称，再拆分子项，不要把多个子项压成一行。
- 单个筛选项如果只是同一对象的多个属性说明，如排序方式、默认值、候选项、单选/多选，优先合并在同一条测试点中表达，不单独拆成多个子点。
- 如果材料出现“与 XX 配合使用”“依赖 XX”“未选择 XX 时提示”“仅在 XX 后展示”，除了单独写联动校验，还要把这条约束挂回该筛选项本身。
- 默认值、前后包含、单选、多选、选填、必填、toast 提示触发条件，材料明确时必须保留，不要只保留筛选范围。
- 组合筛选、切换页码后筛选、筛选后重置、重新筛选后结果刷新、无结果场景，只有材料明确支持时才输出。
- 不把通用筛选场景挂在“搜索按钮”下面。
- 若页面明显存在分页控件或每页条数设置，且材料未否定这些场景，优先补“分页后筛选”“切换页码后结果正确”“切换每页条数后结果正确”。

推荐：

```plaintext
列表筛选
	单筛选项筛选正确
		爆品值筛选：支持按爆品值筛选，筛选结果正确
		账户名称筛选：支持按账户名称关键字模糊搜索；支持点击筛选和按 Enter 触发
		授权状态筛选：单选
		排序筛选：单选；支持发布时间、浏览量、下载量、收藏量、复制到剪映量的高低选择排序；默认降序
		团队/分组/作者筛选
			作者：支持输入账号姓名或直接选择搜索，多选
			团队：支持输入团队名称或直接选择搜索
			分组：支持输入名称或直接选择搜索
	组合筛选，筛选结果正确
	切换页码后筛选，筛选结果正确
	筛选后点击重置，重置筛选项，刷新页面显示全部数据
```

### 列表

- 所有表格和列表统一放在“列表”模块下。
- 字段优先写成“字段名：展示规则”。
- 列、操作列、勾选、全选、分页、跳页、每页条数，只在材料明确展示时输出。
- 列表内操作打开弹窗、抽屉或二级页时，把后续内容挂在该操作项下。
- 对列表字段，不要只写“展示正确”。优先下沉补充以下测试信息：
  - 字段语义
  - 展示格式
  - 默认值或回显值
  - 统计口径
  - 去重口径
  - 联动口径
  - 快照口径

- 如果材料已经明确字段口径，例如：
  - “一个视频被多人下载只算 1 次”
  - “一个素材多个版本算 1 个”
  - “修改率 = 修改次数 / 上传视频数”
  - “平台过审率 = 过审数 / 被推送作品数”
  则必须把这些规则沉到对应字段测试点下，不得只保留字段存在性。

推荐：

```plaintext
列表
	字段展示正确
		广告账户：同一单元格展示账户名称和账户 ID
	操作列
		关联设置
			点击后打开关联设置弹窗
```

### 按钮、弹窗、抽屉

- 后续内容挂在触发它的按钮、链接或操作项下。
- 弹窗内容优先保持在同一入口点下收敛表达，先写“点击后打开/显示某弹窗”，再按排序规则、记录规则、字段展示正确、按钮或关闭方式归并，不要把弹窗内容拆成多个分散子层。
- 表单类弹窗优先按“打开弹窗 / 弹窗标题 / 弹窗字段 / 弹窗操作”这一组结构输出。
- 只有批量类弹窗，或明显依赖勾选记录的弹窗，才补“未勾选记录时 / 勾选记录后”这组入口前置条件。
- 优先提取标题、字段、字段约束、联动、确认、取消、关闭、保存回显。
- 材料明确未展示取消按钮时，直接写“未展示取消按钮”。
- 禁止用“按弹窗要求填写”“按页面要求选择”“正常填写”“正常提交”补齐未知规则；材料没有明确字段规则时，只写字段名称或不展开该字段。

表单类弹窗推荐收敛写法：

```plaintext
批量关联
	未勾选记录时，点击批量关联，提示请选择记录
	勾选记录，点击批量关联，显示“批量关联”弹窗
		弹窗标题：批量设置
		弹窗字段
			关联用户：点击显示用户账户-用户名称组件，单选限制，选填
			关联团队小组：下拉选择，与关联用户所属团队小组联动，不可单独设置/修改，仅回显
			关联分类：点击显示成品下的所有一二级分类信息，单选限制，选填
		弹窗操作
			点击确定：关闭弹窗并修改信息
			点击x：关闭弹窗，不修改信息
			点击取消：关闭弹窗，不修改
```

- 上述结构为优先模板；其中“未勾选提示 / 勾选后打开弹窗”仅用于批量类或勾选依赖类弹窗。取消按钮、字段联动、是否单选或选填等，仅在材料明确支持时输出。

### 功能权限

- 无额外说明时，默认补充功能权限测试点；权限测试点优先挂到真实操作按钮或操作入口下，不单独抽象成“权限模块”。
- 新功能页面默认覆盖页面内有业务影响的操作按钮；迭代需求默认只覆盖本次迭代新增、修改或新增暴露的操作按钮，不补全页面全部存量功能。
- 无特殊说明时，不把筛选、重置、分页、排序、刷新这类查询交互当作功能权限点；只有材料明确说明这些交互也受权限控制时才输出。
- 权限测试点优先覆盖三层：有权限时入口可见且点击不拦截；无权限时入口不可见；无权限时通过分享链接、直达链接、浏览器历史或缓存残留入口触发操作时，前端拦截并提示无权限。
- 接口层必须单独覆盖：无权限账号直接调用相关接口时，接口返回无权限；不要因为前端已隐藏按钮而省略接口鉴权测试点。
- 接口粒度尽量细到真实接口类型，如初始化接口、查询接口、提交接口、导出接口、下载接口；材料未明确接口拆分时，可写为“相关接口”。
- 权限测试点只验证“能否看到入口、能否触发操作、接口是否拦截”；“导出结果正确”“保存结果正确”这类内容属于功能正确性，不并入权限测试点，除非用户明确要求一起覆盖。
- 若页面中同时存在菜单级权限和按钮级权限，优先拆成：
  - 菜单权限
  - 功能权限
  避免把两者混写成一层。

推荐：

```plaintext
操作按钮
	导出
		有权限时，展示“导出”按钮；点击后不拦截，可正常发起导出接口
		无权限时，不展示“导出”按钮
		无权限时，如通过分享链接、直达链接、浏览器历史或缓存残留入口触发导出，前端拦截并提示无权限
		无权限账号直接调用导出相关接口时，接口返回无权限
			导出接口
			导出结果下载接口/下载链接
	绑定用户/分类
		有权限时，展示“绑定用户/分类”按钮；点击后不拦截，可正常发起绑定用户/分类相关接口
		无权限时，不展示“绑定用户/分类”按钮
		无权限时，如通过分享链接、直达链接、浏览器历史或缓存残留入口进入绑定用户/分类场景，前端拦截并提示无权限，不打开弹窗
		无权限账号直接调用绑定用户/分类相关接口时，接口返回无权限
			绑定初始化接口
			用户查询接口
			分类查询接口
			绑定提交接口
```

### 批量操作

- 位于筛选区和列表之间、且依赖勾选结果的按钮，按列表级批量操作处理。
- 材料明确时，覆盖未勾选、已勾选、是否仅作用于已选项、操作后列表刷新。
- 单选、多选、全选、跨页勾选、混合状态，仅在材料明确支持时输出。

### 记录类内容

- 如果记录页面或弹窗是由某个按钮打开，挂在该按钮下，不单独新增顶层“操作记录”模块。
- 优先覆盖排序顺序、时间格式、变更字段完整性、多字段变更的合并展示。
- 记录类弹窗推荐收敛写法：

```plaintext
操作记录
	点击显示操作记录弹窗
		排序规则：按时间倒序展示操作记录
		记录规则：同一次操作涉及多个字段变更时合并展示正确
		字段展示正确：展示操作时间（年月日时分秒）、操作人、变更内容
```

### 外部系统

- 涉及 OA 或其他外部系统时，明确写出数据来源和维护边界。

推荐：

```plaintext
关联用户
	用户列表来自 OA 同步
		新增、删除由 OA 维护，本页面不维护
```

## 特殊材料处理

### 编号备注或标注图

- 备注编号能对应页面控件时，将备注内容挂到对应控件或对应模块下。
- 同一编号在多张截图重复出现时，只保留一次有效规则。
- 编号备注如果只描述控件属性，直接落在该控件测试点下，不额外新建模块。

### 变更说明或版本表

- 版本表中的“新增”“删除”“暂时处理”“与某页面一致”等描述，要合并进对应模块。
- “与某页面一致”“与某平台一致”属于范围说明，可以转写为模块级一致性测试点。
- “暂时处理”“不处理”要明确写出，不扩展未描述逻辑。
- 若为迭代需求或版本说明，功能权限测试点仅对版本说明涉及的新增或调整按钮补充，不扩展其他未提及操作。
- 对版本说明中已经明确给出计算口径、显示口径、字段含义、去重规则、默认范围的内容，必须沉到具体字段或具体模块下，不要只保留在“版本说明”层。

### 混合材料

- 同时给出整页图、局部图、备注、变更说明时，先以整页图定模块，再用其他材料补细节。
- 局部材料只补充已有模块，不随意扩展出整页未出现的新模块。

## 最终检查

- 答案在一个 `plaintext` 代码块内。
- 只包含测试点。
- 没有超出当前范围。
- 所有下级层级均为 Tab 缩进。
- 每个测试点都有材料依据。
- 没有重复顶层模块。
- 局部图、备注、版本说明都挂在正确入口点或模块下。
- 画布上可见的筛选项都已进入“列表筛选/筛选区”，没有只提取带说明或带注释的筛选项。
- 原文中出现的“默认”“配合使用”“联动”“依赖”“单选”“多选”“选填”“必填”“包含”“提示”“未选择”“已选择”等关键词，结果中都有对应落点，没有漏挂。
- 已按默认规则补充功能权限测试点，并区分新功能页面与迭代需求范围；权限点只落在真实操作入口与接口鉴权层，没有把普通查询交互误写成功能权限点。
- 输出应更接近“测试点评审稿”而不是“需求复述稿”：
  - 是否拆出了单筛选项、组合筛选、分页后筛选、重置
  - 是否拆出了统计区、列表字段、弹窗字段、分页、导出、图表或指标切换
  - 是否把字段口径、去重口径、默认值、边界规则沉到具体字段下
  - 是否区分了菜单权限与功能权限
  - 是否对材料未明确支持的测试经验补充做了边界标记，而不是直接写成需求事实
