# 两阶段迁移报告编排补充清单

## 何时读取

当你已经拿到核验结果，但还需要统一报告结构时，读取本文件。典型关键词：

- 中间表、映射表、快照表、批次表
- `source_json`、`extra_json`
- 重跑、补跑、回放
- 文件 URL 重写、对象存储、MinIO
- 差异样例、字段覆盖、失败原因总结

## 报告关注对象

报告中把结果拆成四层展示，不要混写：

1. `源基准层`：第三方接口、源库、导出文件、源基线。
2. `中间层`：映射表、批次表、快照表、文件任务表、临时落地表。
3. `目标层`：业务主表、关系表、分类表、权限表、文件路径字段。
4. `结果层`：目标开放接口、文件 URL、对象存储、页面抽样结果。

## 主报告优先顺序

主报告优先让读者先看懂“链路和结论”，再看“证据和差异”：

1. 核验范围与口径
2. 核验时间证据
3. 阶段一结果
4. 阶段二结果
5. 全链路结果
6. 覆盖缺口与范围限制
7. 字段覆盖总结
8. 差异样例
9. 失败原因总结

不要从第一屏就堆详细差异表。

## 范围与时间拆分

`核验范围与口径` 只放“筛选条件和核验口径”：

- 核验对象
- 核验类型
- 时间筛选范围
- 批次范围
- 环境
- 对象数量

`核验时间证据` 只放“实际时间证据”：

- 报告生成时间
- 批次执行窗口
- 源时间字段实际范围
- 目标时间字段实际范围

例如：

- `上传时间范围` 放在 `核验范围与口径`
- `源 createTime 范围`、`目标 create_time 范围` 放在 `核验时间证据`

## 覆盖缺口单独成章

如果某个维度没有被真正覆盖，不要把它写成：

- `0 条`
- `未形成独立样本`
- `未发现已识别差异`

除非这个维度真的已经独立核验完成。

以下情况统一进入 `覆盖缺口与范围限制`：

- 未做目标层反向全量扫表
- 仅能通过批次参数间接证明筛选范围
- 没有对象存储直接证据
- 没有文件任务表或状态证据
- 只按映射命中链路确认，未做反向覆盖

这一章必须带状态：

- `WARN`：部分可证明，但覆盖不完整
- `BLOCKED`：缺少直接证据，无法判断

## 差异样例最少字段

每条样例至少保留：

- 业务键
- 源标识
- 中间层标识
- 中间层证据
- 目标标识
- 差异类型
- 差异字段
- 差异说明

`中间层证据` 必须优先展示：

- 快照字段值
- 中间层任务状态
- 批次参数
- 文件任务状态

不要拿 `old_id -> new_id` 这种纯映射链重复充当“中间层证据”。

文件类差异额外补充：

- 源 URL
- 中间层 URL 或路径
- 目标 URL 或路径
- 文件大小/时长

## 字段覆盖展示原则

字段覆盖章节用于解释：

- 为什么某些字段只存在中间层
- 为什么某些字段不进入业务表
- 为什么某些字段在目标表是默认值、空串、NULL 或系统生成

不要把字段覆盖章节写成失败清单，除非已有核验结论明确判定这些字段必须迁移。

## 结论用语限制

统一使用：

- `PASS`
- `WARN`
- `FAIL`
- `BLOCKED`

不要混用“通过但失败”“基本通过但阻塞”等模糊表述。

## 自检重点

交付前重点检查：

1. 摘要、结论、差异章节是否前后一致。
2. 是否误把覆盖说明写成失败。
3. 是否因为明细太多导致主报告难读。
4. 是否存在敏感信息未脱敏。
5. HTML 按 UTF-8 重新读取后是否有乱码。
