# 接口测试设计

## 目标

使用本 Skill 时，先把接口文档或接口变更转成接口契约模型，再生成可评审的测试点和可执行的测试用例。本 Skill 只沉淀通用接口测试设计方法，不写入 Linker、加密网关或项目私有执行规则。

## 必须执行的流程

1. 明确测试对象：接口名称、请求方法、请求路径、调用方、目标服务、数据域、环境和变更范围。
2. 读取接口材料：接口文档、Swagger/OpenAPI、PRD、变更说明、请求/响应示例、代码路由或已有用例。
3. 在项目内工作时，先检查 `testcases/<接口名称>测试矩阵.md` 是否存在；若用户只是执行、复测或回归且矩阵仍覆盖当前接口契约，不得重新生成用例，应提示复用矩阵并交给执行 Skill。
4. 首次设计、接口参数变更、矩阵缺失、矩阵与当前契约不一致或用户明确要求重新设计时，生成用例前必须先建立接口契约模型，参考 `references/contract-analysis.md`。
5. 基于契约模型生成测试点矩阵，参考 `references/test-point-matrix.md`。
6. 将矩阵沉淀为项目 `testcases/<接口名称>测试矩阵.md`，一个接口一个基线文件，不带日期时间戳；历史快照或执行记录可另行带时间戳保存。
7. 矩阵必须表达应覆盖的测试设计全集，不得创建“待数据覆盖矩阵”或因当前环境、权限、测试数据不足把权限、异常、边界、数据一致性场景拆出主矩阵；数据前置和可执行性写入前置条件、请求参数重点或执行备注，执行状态由执行阶段判断。
8. 只把有材料支撑的测试点转成测试用例，参考 `references/testcase-template.md`。
9. 设计断言与证据采集要求，参考 `references/assertion-design.md`。
10. 对材料未明确支持的规则标记为“待确认”，不得把猜测写成预期结果。

## 输出要求

当用户要求测试点时，使用 markdown 的 `plaintext` 代码块，并使用真实 Tab 缩进：

```plaintext
模块
	测试点
		校验点
```

当用户要求测试用例时，使用以下结构：

```plaintext
用例编号
	用例标题
	前置条件
	操作步骤
	校验点
	预期结果
```

接口用例必须写清请求 URL、请求方法、请求头、请求参数/请求体、响应断言、异常场景和权限场景。若后续需要执行自动化或接口调用，必须补充证据采集字段。

## 用例身份门禁

生成或整理接口测试用例时，必须先判定每条记录的身份，再进入统计和报告：

- 只有当前测试类型定义的核心可执行用例可计入核心接口用例；普通接口测试默认使用 `API-*`，专项 Skill 或项目规则可声明自己的核心用例前缀。
- 通用接口测试设计不得把某个专项前缀写成全局标准；例如直连网关、UI 自动化、数据库核验、迁移核验等场景的核心前缀必须由对应专项 Skill 或项目规则定义。
- 环境读取、登录、应用配置、凭据检查、接口文档快照、数据准备和诊断步骤只能作为前置、契约或辅助证据，不得计入核心接口用例通过率。
- 一条记录若缺少请求 URL、请求方法、请求头、请求参数/请求体、响应断言和业务断言，不得标记为接口用例。
- 若输出报告，汇总页只展示核心接口用例统计、核心结论和主要风险；全量执行项统计与前置/契约/数据准备/诊断明细只能通过独立链接跳转查看，不得直接堆在汇总页。

## 覆盖门禁

交付前必须覆盖：

- 正常路径
- 边界值
- 非法入参
- 认证与权限
- 存在分页、排序、筛选时的分页/排序/筛选规则
- 适用时的幂等或重复提交
- 新增、删除、废弃、默认参数的兼容性
- 数据正确性与响应字段映射
- 错误码与错误信息
- 当前数据不足但属于应测范围的权限、异常、边界和数据一致性场景

若某个维度不适用，必须在输出或风险说明中写明原因。

## 自审门禁

最终交付前检查：

- 每条用例都能映射到真实接口字段、规则或变更项。
- 必填参数和非必填参数没有混用。
- 参数依赖、互斥和默认行为已覆盖。
- 断言验证业务行为，不只验证 HTTP 状态码。
- 异常用例有明确状态码、业务 code 或 message 预期。
- 测试数据和权限前提已说明。
- 没有把当前测试数据不足的应测场景移出主矩阵。
- 核心接口用例统计未混入前置、契约、数据准备或诊断项。
- 全量执行项若需要保留，已放入独立明细并在汇总页提供链接。
- 未输出明文 token、密码、cookie、密钥或生产敏感数据。
