# 测试点矩阵

使用本矩阵避免接口用例设计停留在“请求成功”层面。

## 正常场景

- 最小合法请求
  - 必须显式成例，不能被“默认分页成功”“仅某一个筛选参数成功”“空结果成功”等零散正向场景替代
  - 仅保留接口成功所必需的输入，其余可选参数全部省略，由服务端默认值、默认筛选口径或默认分页行为接管
- 全量合法组合请求
  - 必须显式成例，不能把互斥参数、冲突参数、条件不满足参数或待确认组合强行塞入同一用例
  - 仅选择当前契约下所有可合法共存的参数进行完整请求，用于验证完整正向链路和参数联动
- 每个独立筛选或动作参数
- 合法参数组合
- 预期有数据返回
- 预期空结果返回

若接口存在两种及以上独立查询模式、筛选模式、翻页模式或续读模式，则每种模式至少设计 1 条全量合法组合请求。
若某种跨模式组合当前文档未明确，则该组合只能保留为待确认/组合规则用例，不得冒充全量合法组合请求。
若接口除鉴权与固定协议字段外不存在业务可选参数，可将“最小合法请求”和“全量合法组合请求”合并为 1 条，并在矩阵中注明“因无可选参数，二者合并”。

## 边界场景

- 字符串最小/最大长度
- 数值最小/最大值和精度
- 时间开始/结束边界是否包含
- 枚举每个合法值
- pageNo/pageSize 最小值和最大值
- 批量数量上限
- 合法筛选条件下的空列表

## 异常场景

- 缺少必填参数
- 参数类型错误
- 参数格式错误
- 非法枚举值
- 超出范围
- null、空字符串、空白字符串
- 开始值大于结束值
- 不支持的参数组合
- JSON 格式错误或 Content-Type 不匹配

## 权限与安全

- 未传 token 或 token 非法
- token 过期
- 无资源权限
- 跨租户、跨店铺、跨账户访问
- 用户角色边界
- 接口存在签名时的签名错误、nonce 重放
- 响应和日志敏感信息脱敏

## 分页、排序、筛选

- pageNo/pageSize 基础查询
- pageSize 上限
- 首页、中间页、末页
- cursor 首次读取和续读
- cursor 与 page 参数同时传
- 跨页不重复、不漏数
- 重复请求排序稳定
- 分页过程中筛选条件持续生效

## 设计门禁

生成矩阵前后，必须检查以下问题：

- 是否已显式输出“最小合法请求”，且该用例能够证明省略全部非必填参数后接口仍可按契约成功
- 是否已显式输出“全量合法组合请求”，且该用例只包含可合法共存参数，不包含互斥、冲突或待确认组合
- 若接口存在多种独立查询模式、筛选模式或续读模式，是否每种模式均至少覆盖 1 条全量合法组合请求
- 是否错误地用“默认分页”“单筛选成功”“分页成功”或“cursor 成功”等局部正向场景替代“最小合法请求”或“全量合法组合请求”
- 若接口无可选参数，是否已在矩阵中明确写明“最小合法请求”与“全量合法组合请求”合并原因

## 兼容性

- 老请求体不传新增参数
- 新参数不传
- 新参数单独传
- 新参数与旧筛选条件组合
- 老客户端仍传废弃参数
- 未知额外参数处理
- 默认值行为

## 数据正确性

- 返回记录符合请求筛选条件
- 业务唯一键能映射到源数据
- 金额精度和舍入
- 时区和时间格式
- 状态和枚举映射
- 主明细数量和关系一致
- 有条件时与数据库或下游数据一致
