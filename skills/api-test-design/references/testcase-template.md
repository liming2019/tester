# 测试用例模板

返回用例时必须使用真实 Tab 缩进。

```plaintext
API-001
	用例标题
		<接口名>-<场景>-<核心参数或规则>
	前置条件
		测试环境、账号、权限、测试数据、依赖服务状态明确
	操作步骤
		1. 构造请求：<METHOD> <URL>
		2. 设置请求头：<headers>
		3. 设置请求参数/请求体：<params/body>
		4. 发送请求
		5. 记录响应状态、响应体、关键日志或数据库结果
	校验点
		HTTP 状态码符合预期
		业务 code/message 符合预期
		响应结构符合契约
		核心业务字段符合请求条件
		数据权限和数据一致性符合预期
	预期结果
		明确写成功、失败、空列表、参数错误、权限错误或兼容通过
```

## 编号规则

- 通用接口用例使用 `API-<模块>-<场景>-NNN`。
- 模块明确时可使用业务前缀，例如 `ORDER-API-001`。
- 每条用例只验证一个核心行为目的。
- 环境、登录、凭据、应用配置、文档快照、数据准备和诊断记录不得使用接口用例编号，也不得计入核心接口用例统计。

## 质量要求

- 不得只写“请求成功”作为预期结果。
- 必须使用接口契约中的真实参数名。
- 异常用例必须写出文档支持的 code/message；文档未定义时标记“待确认”。
- 数据正确性用例必须写明数据来源和业务唯一键。
- 报告汇总页只展示核心接口用例统计；全量执行项和辅助证据应放入独立明细，通过链接查看。
