# 接口契约分析

生成测试点前必须先建立以下模型。

## 接口身份

- 接口名称和业务目的
- 请求方法和请求路径
- 调用方和权限模型
- Content-Type 与编码方式
- 鉴权方式
- 幂等预期
- 目标业务对象和业务唯一键

## 请求契约

对 path、query、header、body 中的每个参数记录：

- 参数名
- 参数位置
- 必填或非必填
- 类型
- 格式
- 长度、范围、精度或正则
- 枚举值
- 默认值
- null、空串、空白串处理
- 示例值
- 业务含义
- 新增、变更、废弃或删除状态

## 参数关系

识别以下关系：

- 互斥
- 一组参数至少传一个
- 父子依赖
- 条件必填
- 跨字段范围规则，例如开始值小于等于结束值
- 分页依赖
- 排序和筛选依赖
- 权限、租户、店铺或账户边界依赖

## 响应契约

记录：

- HTTP 状态码预期
- 业务 code/message
- data 类型和顶层结构
- 必返字段
- 可空字段
- 列表和分页字段
- 业务唯一键
- 金额、时间、状态、枚举映射
- 错误响应结构

## 变更影响

接口变更时必须分类：

- 新增请求参数
- 默认行为变化
- 校验规则变化
- 响应字段变化
- 权限边界变化
- 分页或排序变化
- 向后兼容风险
- 历史数据或数据迁移风险
