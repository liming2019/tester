# 接口契约分析

生成测试点前必须先建立以下模型。

## 接口身份

- 接口名称和业务目的
- 请求方法和请求路径
- 调用方和权限模型
- Content-Type 与编码方式
- 鉴权方式
- 幂等预期
- 目标业务对象和业务唯一键

## 请求契约

对 path、query、header、body 中的每个参数记录：

- 参数名
- 参数位置
- 必填或非必填
- 类型
- 格式
- 长度、范围、精度或正则
- 枚举值
- 默认值
- null、空串、空白串处理
- 示例值
- 业务含义
- 新增、变更、废弃或删除状态

## 参数关系

识别以下关系：

- 互斥
- 一组参数至少传一个
- 父子依赖
- 条件必填
- 跨字段范围规则，例如开始值小于等于结束值
- 分页依赖
- 排序和筛选依赖
- 权限、租户、店铺或账户边界依赖

## 参数语义分组

在开始设计矩阵前，必须先把参数按语义拆组，而不是直接照着示例请求堆场景。至少检查：

- 身份/对象参数，例如 `shopId`、`advertiserId`、`orderId`
- 业务筛选参数，例如状态、类型、平台、店铺、账户
- 业务日期筛选参数，例如 `dateStart/dateEnd`、`bizDate`
- 更新时间筛选参数，例如 `updateTimeStart/updateTimeEnd`
- 分页参数，例如 `pageNo/pageSize`
- 状态参数，例如 `cursor`、`nextToken`
- 权限参数，例如租户、角色、资源范围
- 兼容参数，例如新增参数、废弃参数、未知额外参数

对以下场景必须拆成不同参数组，不能合并成一套测试点：

- 名称相似但业务语义不同，例如 `dateStart/dateEnd` 与 `updateTimeStart/updateTimeEnd`
- 同时服务于不同查询口径，例如“业务发生时间”与“数据同步时间”
- 同时存在“首次查询参数”和“续读状态参数”，例如筛选条件与 `cursor`

若接口存在两套或以上并列筛选维度，后续矩阵必须分别覆盖每一套维度的正常、边界、异常和组合规则。

## 测试技术映射

完成参数分组后，为每一组参数选择测试技术：

- 等价类划分：每个独立参数组至少一次覆盖合法值与非法值
- 边界值分析：适用于长度、范围、页码、页大小、时间跨度、开始/结束值
- 决策表：适用于互斥、条件必填、分页与筛选联动、cursor 与筛选联动
- 状态迁移：适用于首包/续读/重复续读/参数不一致续读等状态链路

若接口存在多个筛选组，至少满足最小 `Each Choice`：每个独立筛选组都要在矩阵中被明确覆盖，不能只覆盖示例里出现的一组。

## 响应契约

记录：

- HTTP 状态码预期
- 业务 code/message
- data 类型和顶层结构
- 必返字段
- 可空字段
- 列表和分页字段
- 业务唯一键
- 金额、时间、状态、枚举映射
- 错误响应结构

## 变更影响

接口变更时必须分类：

- 新增请求参数
- 默认行为变化
- 校验规则变化
- 响应字段变化
- 权限边界变化
- 分页或排序变化
- 向后兼容风险
- 历史数据或数据迁移风险
