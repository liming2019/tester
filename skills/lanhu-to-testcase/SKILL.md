# 蓝湖到测试资产

这个 skill 是**上层编排 skill**。

它只负责一件事：

- 按固定顺序调度蓝湖需求提取、测试对象分析、测试点提取和测试用例整理。

它不负责替代下游 skill 的详细规则，不负责重新定义挂载规则，也不负责在编排层重复书写测试点生成规范。

## 适用场景

当用户表达以下意图时触发：

- “帮我提取蓝湖 xxx 的需求说明，并生成测试点”
- “帮我提取蓝湖 xxx 的需求说明，并生成测试用例”
- “把这个蓝湖版本需求转成测试点”
- “提取 1.4.6 需求说明后生成测试用例”
- “先提取需求，再输出测试点”

## 角色边界

- `lanhu-requirements-extractor`：负责从蓝湖提取结构化事实。
- `test-object-analysis`：负责复杂业务的对象建模、状态/权限/数据关系分析。
- `extract-functional-test-points`：负责把输入材料或结构化需求挂载成可评审测试点。
- `generate-functional-testcases`：负责把已确认测试点整理成普通功能测试用例。
- 本 skill：只负责判断调用顺序、输入输出衔接和终点控制。

## 编排原则

- 先提需求，再生成测试点。
- 复杂业务先建模，再生成测试点。
- 简单页面不强制走复杂对象分析。
- HTML 只用于核验，不作为默认下游输入。
- 默认终点是“测试点”，不是“测试用例”。
- 用户指出漏项时，先回到需求提取层修正，再重跑下游。

## 标准流程

### 第一步：调用需求提取

先调用：

- `$lanhu-requirements-extractor`

目标：

- 获得 `requirements.json`
- 获得按页面组织的结构化需求
- 获得版本过滤后的稳定输入

### 第二步：判断是否需要测试对象分析

满足以下任一情况时，调用：

- `$test-object-analysis`

优先命中场景：

- 涉及账户、资金、权限、状态流转、数据一致性、外部依赖。
- 涉及跨页面流程、上下游链路或异步处理。
- 涉及复杂列表管理、配置中心、投放平台、审核流程。
- 材料中存在较多待确认项，仅靠页面控件无法直接形成高质量测试点。

满足以下情况时，可直接进入测试点提取：

- 单页静态展示或局部交互变更。
- 字段展示、文案、说明、简单弹窗字段补充。
- 页面结构清晰，规则主要停留在界面层，缺少复杂业务对象。

### 第三步：调用测试点提取

调用：

- `$extract-functional-test-points`

输入规则：

- 若第二步已调用 `$test-object-analysis`，优先传入其“下游测试点生成输入”。
- 若第二步跳过对象分析，直接传入 `$lanhu-requirements-extractor` 的结构化需求输出。
- 不在本 skill 内手工重写挂载规则。
- 不在本 skill 内维护“画布注释/说明/交互态如何挂到字段和入口”的下游细则。

### 第四步：如用户明确要求，再生成测试用例

只有当用户明确要求“测试用例”时，才继续调用：

- `$generate-functional-testcases`

输入使用第三步产出的测试点。若用户明确要求的是“UI 自动化测试用例”“自动化用例 Markdown”或“为 Playwright 脚本准备用例”，则改用 `$generate-ui-automation-testcases`，不要把普通功能用例和 UI 自动化用例混在一个产物里。

## 下游调用约束

- 不直接传完整 HTML 作为默认输入
- 不只传截图
- 不丢掉页面名、模块名、版本号
- 若输入来自蓝湖提取结果，优先保留结构化字段，而不是重新整理一份手写摘要
- 挂载规则、去重规则、字段归属规则以 `$extract-functional-test-points` 为准
- 复杂对象拆解、状态/权限/数据关系规则以 `$test-object-analysis` 为准

## 默认输出

默认输出：

1. 结构化需求产物路径或摘要
2. 页面级测试点

只有当用户明确要求时，再补：

3. 测试用例
4. Markdown / HTML / 表格导出
5. XMind / `.xmind` 脑图导出

XMind 仅在用户明确要求时生成。生成后必须先校验文件真实存在、zip 包内内容文件唯一且中文未乱码，再返回本地绝对路径。

XMind 生成前必须先完成并校验页面级 `plaintext` 测试点。XMind 只能由这份 `plaintext` 按 Tab 层级转换，不能在生成 XMind 时重新整理、补写、删减或硬编码测试点。若 `plaintext` 测试点未通过下游测试点 skill 的最终检查，不得交付 XMind。

## 默认终点

当用户只要求以下任一目标时，流程停在“测试点输出”：

- 提取需求说明
- 整理需求
- 输出测试点
- 提取需求后生成测试点

不要默认继续生成测试用例。

只有当用户明确出现以下意图时，才进入测试用例阶段：

- 生成测试用例
- 输出测试用例
- 测试点转测试用例
- 基于测试点整理测试用例

## 完成条件

如果用户只说“提取需求说明并输出测试点”，默认完成条件是：

1. 蓝湖需求提取完成
2. 如命中复杂场景，则测试对象分析完成
3. 测试点提取完成

如果用户明确说“提取需求说明并生成测试用例”，完成条件才是：

1. 蓝湖需求提取完成
2. 如命中复杂场景，则测试对象分析完成
3. 测试点提取完成
4. `generate-functional-testcases` 完成普通功能测试用例整理

## 禁止事项

- 禁止在本 skill 内复制下游 skill 的长篇挂载规则。
- 禁止在本 skill 内手工重写页面级摘要作为长期固定中间层。
- 禁止把 `$lanhu-requirements-extractor` 的结构化 JSON 再改造成另一套事实源 schema。
- 禁止无差别强制所有蓝湖页面都走 `$test-object-analysis`。
- 禁止跳过需求提取直接从截图生成“蓝湖测试点”。
