# 蓝湖到测试用例

这个 skill 是**上层编排 skill**。

职责是：

1. 调用 `$lanhu-requirements-extractor`
2. 获取标准化需求数据
3. 整理成适合测试分析的页面级摘要
4. 调用 `$test-object-analysis` 先拆测试对象、状态、权限、数据关系、风险和待确认项
5. 调用下游测试点提取 skill
6. 仅在用户明确要求时，再继续整理为测试用例

它不负责替代蓝湖提取，也不负责自己定义测试规则。

## 适用场景

当用户表达以下意图时触发：

- “帮我提取蓝湖 xxx 的需求说明，并生成测试用例”
- “把这个蓝湖版本需求转成测试点”
- “提取 1.4.6 需求说明后生成测试用例”
- “先提取需求，再输出测试点”

## 编排原则

- 先提需求，再提测试点
- 先页面级归一化，再全量汇总
- HTML 只用于核验，不作为下游输入源
- 用户指出漏项时，先修需求提取，再更新测试点
- 默认终点是“测试点”，不是“测试用例”

## 标准流程

### 第一步：调用需求提取

先调用：

- `$lanhu-requirements-extractor`

目标：

- 获得 `requirements.json`
- 获得稳定页面列表
- 获得按来源分组的需求数据

### 第二步：整理页面级测试输入

不要把整个原始 JSON 生硬塞给下游。

应把每个页面整理成统一模板：

```text
项目：云视频
版本：1.4.6
页面：爆品设置V1.4.6
模块：内容管理 / 爆品设置

一、原型正文说明
- V1.4.6 / 爆品设置 / 不同分类进行不同消耗的爆品值定义，可以批量设置，列表显示独立
- V1.4.6 / 权限 / 添加爆品设置菜单权限；新增、编辑和删除权限

二、画布内注释
- A1 / 名称 / 一开始没有，根据后台分销等级设定后显示

三、画布内说明文案
- 爆品值 / 该分类下的视频累计消耗到此值后将会被定义为爆品

四、交互态内容
- 触发入口 / 交互方式 / 结果类型 / 实际标题 / 实际字段 / 实际操作

五、右侧页面说明
- 创建时间 / 新建成功的时间

任务：
请基于以上需求说明提取可测试的功能测试点，如有必要再整理为测试用例。
```

注意：第二步可以保留五类来源分组，便于下游理解来源；但第三步输出测试点时，`画布内注释` 和 `画布内说明文案` 不应作为独立模块展示。它们必须优先挂到真实字段、控件、操作项或列表列名下。例如“爆品值”的画布说明应出现在 `列表 -> 字段展示正确 -> 爆品值` 的子点中，“创建时间”的注释应出现在 `创建时间` 字段子点中。

交互态内容也不能单独输出成无来源的“弹窗”模块。比如“新增爆品”点击后显示新增弹窗，下游测试点必须挂到 `操作按钮 -> 新增爆品` 下，再展开实际抓取到的弹窗标题、字段和操作。不要用“按弹窗要求填写”“正常提交”这类空泛话术补齐未知规则。

### 第三步：调用测试对象分析 skill

调用：

- `$test-object-analysis`

输入第二步整理后的页面级摘要，先输出：

- 测试对象地图
- 对象状态与规则矩阵
- 权限边界清单
- 数据一致性检查点
- 风险场景清单
- 待确认问题清单
- 下游测试点生成输入

如果是多页面，应逐页完成对象分析，再统一汇总。不得跳过对象分析直接生成测试点；若页面仅涉及单一文案、样式或静态展示变更，可在对象分析结论中说明“无需展开复杂对象建模”，再进入测试点提取。

### 第四步：调用测试点提取 skill

调用现有测试点提取 skill，优先输入第三步产出的“下游测试点生成输入”；必要时附带第二步页面级摘要作为来源补充。

如果是多页面，应逐页生成测试点，再统一汇总。

### 第五步：如需要，继续生成测试用例

只有当用户明确要求“测试用例”时，才在测试点基础上继续整理为：

- 用例标题
- 前置条件
- 操作步骤
- 预期结果

## 下游调用约束

传给测试点 skill 时必须遵守：

- 不直接传完整 HTML
- 不只传截图
- 不丢掉页面名、模块名、版本号
- 同一页面的五类需求来源保留分组
- 某类来源为空时可以省略该小节
- 下游最终测试点中，画布说明和注释必须内嵌到字段级或操作级测试点；不能因为上游摘要分组而输出独立的“画布内说明文案”或“画布内注释”模块
- 下游最终测试点中，交互态内容必须内嵌到触发入口下；不能因为上游摘要分组而输出独立的“弹窗”“抽屉”或“二级页面”顶层模块

## 推荐输出

默认输出：

1. 页面级需求摘要
2. 页面级测试点

只有当用户明确要求时，再补：

3. 测试用例
4. Markdown / HTML / 表格导出
5. XMind / `.xmind` 脑图导出

XMind 仅在用户明确要求时生成。生成后必须先校验文件真实存在、zip 包内内容文件唯一且中文未乱码，再返回本地绝对路径。

XMind 生成前必须先完成并校验页面级 `plaintext` 测试点。XMind 只能由这份 `plaintext` 按 Tab 层级转换，不能在生成 XMind 时重新整理、补写、删减或硬编码测试点。若 `plaintext` 测试点未通过下游测试点 skill 的最终检查，不得交付 XMind。

## 默认终点

当用户只要求以下任一目标时，流程必须停在“测试点输出”：

- 提取需求说明
- 整理需求
- 输出测试点
- 提取需求后生成测试点

不要默认继续生成测试用例。

只有当用户明确出现以下意图时，才进入测试用例阶段：

- 生成测试用例
- 输出测试用例
- 测试点转测试用例
- 基于测试点整理测试用例

## 可继续加工的结构

建议保留一个中间结构：

```json
{
  "source": {
    "platform": "lanhu",
    "domain": "ysp",
    "version": "1.4.6"
  },
  "pages": [
    {
      "page_name": "爆品设置V1.4.6",
      "requirement_summary": [],
      "test_points": [],
      "test_cases": []
    }
  ]
}
```

## 完成条件

如果用户只说“提取需求说明并输出测试点”，默认完成条件是：

1. 蓝湖需求提取完成
2. 页面级需求摘要完成
3. 测试对象分析完成
4. 测试点提取完成

如果用户明确说“提取需求说明并生成测试用例”，完成条件才是：

1. 蓝湖需求提取完成
2. 页面级需求摘要完成
3. 测试对象分析完成
4. 测试点提取完成
5. 如果要求测试用例，则测试用例整理完成
