# UI 自动化测试用例输出模板

仅在生成最终用例文件前参考本模板；不要把模板说明原样复制进最终产物。

## 标准章节

最终文件默认包含以下章节：

1. `# <页面或模块><版本> UI 自动化测试用例`
2. `## 基本信息`
3. `## 待确认项`
4. `## 用例明细`
5. `## 自动化脚本拆分建议`
6. `## 后续优化建议`（可选）

## 基本信息表

```markdown
## 基本信息

| 项 | 内容 |
| --- | --- |
| 来源文件 | `testpoints/...` |
| 转换范围 | 页面/模块 |
| 输出目标 | Playwright Python UI 自动化测试用例基线 |
| 适用环境 | test/dev |
| 转换说明 | 简述本次转换边界 |
```

## 用例表头

```markdown
| 用例ID | 页面 | 功能区 | 用例标题 | 优先级 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 脚本分组建议 | 可自动化 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
```

## 字段填写规则

- `用例ID`：按页面前缀连续编号，例如 `UI-CAT-001`。
- `页面`：写用户可理解的页面名，例如“分类”。
- `功能区`：写一级分类、二级分类、关联标签组、页面框架、弹窗等。
- `用例标题`：必须可单独阅读，不要写成“校验正确”这种缺主语标题。
- `优先级`：默认使用 `P0/P1/P2`。
- `前置条件`：只写执行此用例真正需要的页面状态、角色、数据前提。
- `测试数据`：写关键数据，不写“正常数据”这类空泛描述。
- `操作步骤`：建议使用 `1. 2. 3.`，步骤中只保留用户动作。
- `预期结果`：只写可断言结果，不混入操作过程。
- `脚本分组建议`：写目标脚本文件名，例如 `test_category_manage.py`。
- `可自动化`：常用值 `是`、`是，需造数`、`待确认`、`否，需联合断言`。
- `备注`：放版本冲突、已下线功能、需接口/数据库断言、依赖外部数据等补充说明。

## 典型拆分示例

源测试点：

```markdown
- 新增分类&编辑分类弹窗：
  - 弹窗标题正确
  - 名称必填
  - 名称不支持重复
  - 199/200/201 字边界正确
  - 点击右上角 x 关闭弹窗
  - 点击确定按钮提交成功
```

推荐拆分结果：

1. 弹窗标题显示正确
2. 名称必填与空白校验正确
3. 名称重复校验正确
4. 名称长度边界校验正确
5. 点击右上角关闭按钮关闭弹窗且不提交
6. 点击确定后关闭弹窗并刷新页面显示操作结果

## 不要这样输出

- 不要把“页面规则”里一长串静态文案逐行转成几十条伪用例。
- 不要把一个页面下所有动作塞成一条“大而全”用例。
- 不要在缺少页面 URL、权限口径、数据条件时擅自补全。
- 不要直接输出 Playwright 代码；本模板只用于生成 UI 自动化测试用例文档。
