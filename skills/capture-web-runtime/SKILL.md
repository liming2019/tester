# 采集页面运行态

使用本 Skill 时，只负责采集真实浏览器运行态材料，不负责下最终定位结论。

## 共享 references

开始前先读取：

- [共享规则](../ui-locator-orchestrator/references/ui-locator-guidelines.md)
- [运行态材料包 schema](../ui-locator-orchestrator/references/runtime-capture.schema.json)

重点遵守其中的“运行态材料包约定”“状态命名”“何时要求前端补测试锚点”，并让 `summary.json` 满足 `runtime-capture.schema.json`。

## 最小输入

1. 目标页面 URL 或页面路径。
2. 认证注入方式与键名。
3. 是否指定模块；若指定，给出模块名称、区域选择器、业务区域描述或明确动作。
4. 页面稳定条件，例如 `wait-selector` 或可接受的 `settle-ms`。
5. 需要覆盖的页面状态或交互步骤，例如打开弹窗、切换页签、执行搜索。
6. 输出目录或产物归档位置。

## 工作流

1. 确认认证注入方式。优先 `header`，其次 `cookie`、`local-storage`、`session-storage`；只有页面本身要求时才用 `query`。
2. 确认页面稳定锚点。已知锚点时优先等待选择器；否则使用页面加载完成加额外稳定等待。
3. 判断抓取范围。未指定模块时，默认抓整页范围内可见、可操作元素，以及业务动态操作元素；指定模块时，只抓该模块和该模块触发的业务动态区域。
4. 先抓默认态：页面标题、最终 URL、整页或模块级截图、可见元素摘要、关键 DOM 或结构化快照、a11y 语义摘要。
5. 未指定模块时，主动扫描安全动态入口，并把它们加入状态矩阵。至少扫描：标准 button/link、表格行内按钮、自定义 `div.add`、图标+文字入口、自定义可点击标题栏操作、下拉箭头、级联箭头、树展开按钮、更多菜单入口。
6. 再按状态矩阵逐个执行交互：例如搜索、翻页、展开树节点、打开弹窗、切换标签页，并为每个状态单独保存材料。
7. 对表格、弹窗、树、分页、抽屉、下拉、级联等局部区域，补抓区域级截图和触发动作说明。
8. 汇总异常结构，例如 iframe、shadow DOM、portal、虚拟滚动列表、懒加载区块。

## 执行规则

- 优先复用现有 `capture-web-elements/scripts/capture_elements.py`；需要更丰富的运行态材料时，基于它扩展或二次处理，不要平行造一套脱节脚本。
- 不要在聊天中回显 token、cookie 或真实账号。
- 输出内容以“材料包”为目标，不要把一次抓取强行包装成最终定位结论。
- 未指定模块时，默认执行整页抓取；不要擅自缩到单一区域。
- 指定模块时，默认执行模块级增量更新；除非用户要求，不要顺带刷新全页面其他模块。
- 未指定模块时，若发现安全动态入口，默认必须展开采集其内部元素；不要只记录入口本身。
- 动态入口发现应覆盖自定义可点击元素，不只依赖原生 button/link。至少结合可见文本、图标组合、业务容器类名、`cursor:pointer`、可访问属性综合判断。
- 必须区分默认态和交互后状态，不能只保留最后一个页面状态。
- 若页面需要多步导航才能进入目标区域，要记录进入路径和每步触发动作。
- 若抓取过程中发现页面尚未稳定、元素闪烁、列表虚拟化导致 DOM 不全，必须显式标记。
- 必须记录哪些动态触发器已被覆盖，例如“新增按钮”“行内编辑按钮”“角色下拉”“更多菜单”。
- 若某动态入口展开后没有新业务元素，应记录“已展开但无新增元素”，不要静默跳过。

## 建议输出结构

- `summary.json`：抓取参数、页面标题、最终 URL、状态矩阵、异常说明；结构满足 `runtime-capture.schema.json`。
- `screenshots/`：默认态和各状态截图。
- `snapshots/`：DOM、结构化元素、a11y 摘要或其他中间材料。
- `events.json`：每个状态由什么动作触发、抓取时机和关键等待条件。

## 完成后的回复

只汇报：

1. 页面标题和最终 URL。
2. 覆盖了哪些页面状态。
3. 产物目录和关键文件路径。
4. 主要异常和可能影响后续定位分析的点。
