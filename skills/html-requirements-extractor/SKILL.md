# HTML 原型需求提取

本 Skill 是 **HTML 原型需求标准化提取器**。职责是把 HTML 原型中的需求事实提取成统一 `requirements.json`，供 `$test-object-analysis`、`$extract-functional-test-points`、`$generate-functional-testcases` 等下游 Skill 使用。

不要把本 Skill 与 `$lanhu-requirements-extractor` 混用：蓝湖页面、蓝湖 iframe、蓝湖注释点仍走蓝湖 Skill；直接可访问的 `.html` 原型、本地 IP 原型、产品导出的 HTML 页面走本 Skill。

## 输入判断

优先使用本 Skill 的情况：

1. URL 或文件名包含 `.html`，且页面本身就是原型内容。
2. 页面来自 `localhost`、内网 IP、静态资源服务或产品原型目录。
3. 页面可直接看到业务导航、筛选区、表格、弹窗、抽屉、需求说明文档。
4. 用户要求按版本、平台、Tab 或页面入口提取 HTML 原型需求。

继续使用蓝湖 Skill 的情况：

1. 需要登录蓝湖。
2. 原型在蓝湖外壳、iframe 或 Axure 注释点中。
3. 需求来源依赖蓝湖右侧页面说明、画布注释或蓝湖运行时数据。

## 标准流程

1. 打开或读取 HTML 原型。
2. 识别页面标题、URL 参数、hash、版本、媒体平台、当前 Tab。
3. 若用户指定目标版本，必须先定位版本目录入口：
   - URL 已在 `Vx.y.z/` 目录下时，优先尝试同目录 `index.html` 或版本首页。
   - URL 是某个业务页面时，不得只从当前页面提取；必须回到版本首页或侧边目录收集同版本页面。
   - 侧边目录、页面标题、需求表或版本标识中任一命中目标版本，都要纳入候选页面，再按单条需求做版本过滤。
4. 建立页面扫描清单，记录候选页面、命中依据、访问结果和是否纳入本次提取；无法访问的页面也要记录为证据或质量提示。
5. 提取需求说明表，优先识别表头为 `版本 / 版本内容 / 说明` 的表格。
6. 按目标版本过滤，版本不匹配的内容不得进入最终需求。
7. 提取页面结构：侧边导航、媒体 Tab、功能 Tab、筛选字段、按钮、表格列、指标卡、流程说明。
8. 提取交互态：弹窗、抽屉、隐藏区块、详情页、Tab 切换后的字段和按钮。
9. 对同一 `版本内容` 去重，保留说明更完整的一条，并记录来源页面、来源区块和重复来源。
10. 对每个命中需求建立“页面关联”：需求 ID、页面、区域、入口、交互对象、影响字段、输出结果，不得只保留需求标题。
11. 输出 `requirements.json`；需要人工评审时再补 Markdown 或 HTML 摘要。
12. 检查“页面有明显交互入口但 interaction_states 为空”的风险。

## 字段级提取要求

HTML 原型需求提取不能停留在“表格列名”或“按钮名”层级。生成 PRD、测试点或用例前，必须补齐字段级规则：

1. 复合字段必须拆解子字段。例如表头为“广告账户”，但单元格中上下两行展示账户名称和账户 ID 时，必须标记为“广告账户名称 + 广告账户 ID”，并记录展示顺序。
2. 列表、表格、卡片、弹框和抽屉都要提取字段组成：
   - 表格：表头、行内字段、复合单元格、选择框、状态标识、金额/日期单位、空态。
   - 弹框：顶部提示、Tab、筛选项、左侧/右侧区域、列表字段、底部状态、底部按钮、按钮禁用条件。
   - 卡片：主标题、副标题、ID、标签、状态、时间、金额、入口按钮。
3. 搜索框必须提取“可搜索字段”和“匹配颗粒度”：
   - 原型或需求说明明确匹配方式时，以明确说明为准。
   - 原型或需求说明未明确匹配方式时，名称/标题/文本类字段默认模糊查询，ID/编号/code/key 类字段默认精准匹配。
   - 多字段搜索要说明是任一字段命中还是全部字段同时命中；未明确时列为待确认，不得自行扩大为全部命中。
4. 选择和批量操作必须提取选择范围：单选、多选、全选当前筛选结果、跨页全选、禁选项、已选数量展示、清空或重置规则。
5. 按钮必须提取可用条件和结果：
   - 保存类按钮要说明是否关闭弹框、是否保留弹框、是否反馈成功数量、是否生成结果记录。
   - 原型未出现的操作不得补写为需求；若业务规则显示缺少该操作会造成闭环风险，只能进入待确认项，等待用户确认后再改为正式规则。
6. 数据口径字段必须提取统计范围、时间范围、去重规则和来源关系。出现“累计”“追溯”“合计”“日期筛选”等词时，必须检查口径是否冲突；未明确则列为 P0/P1 待确认项。
7. 用户后续确认的口径必须写入 `confirmed_rules` 或 PRD“已确认口径”，并同步移除相冲突的待确认项、风险项和质量建议。

## 脚本优先

优先运行随 Skill 提供的脚本：

```bash
python scripts/extract_html_requirements.py --url "<prototype-url>" --version "V1.6.1" --output "<output-json>"
```

也支持本地 HTML 文件：

```bash
python scripts/extract_html_requirements.py --file "<prototype.html>" --version "V1.6.1" --output "<output-json>"
```

常用参数：

- `--media`：只保留指定媒体平台相关内容，例如 `磁力金牛`。
- `--tab`：记录当前 Tab 或目标 Tab，例如 `allSiteDetail`。
- `--summary-md`：额外输出人工可读 Markdown 摘要。
- `--raw-html`：保存原始 HTML 副本，便于追溯。

脚本只负责提取结构化需求事实，不负责直接生成测试用例。

## 输出结构

主输出固定为 `requirements.json`。推荐顶层结构：

```json
{
  "source": {
    "platform": "html-prototype",
    "version": "V1.6.1",
    "title": "页面标题",
    "url": "原型地址",
    "media": "媒体平台",
    "tab": "当前 Tab"
  },
  "pages": []
}
```

每个页面对象至少包含：

- `page_name`
- `page_url`
- `page_group`
- `page_module`
- `screenshot`
- `prototype_structured`
- `canvas_annotations`
- `canvas_text_notes`
- `interaction_states`
- `right_panel_notes`
- `raw_prototype_text`
- `page_components`

字段约束：

- `prototype_structured`：数组，元素字段固定为 `版本`、`版本内容`、`说明`、`version_match`、`included_in_target_version`、`source_section`。
- `canvas_annotations`：HTML 原型通常为空数组，除非页面中有明确注释编号。
- `canvas_text_notes`：页面内说明、流程说明、提示文案。
- `interaction_states`：弹窗、抽屉、隐藏详情、Tab 状态等，字段包含 `trigger`、`trigger_type`、`interaction`、`result_type`、`title`、`fields`、`actions`、`notes`、`screenshot`。
- `right_panel_notes`：HTML 原型通常为空数组，除非页面模拟了右侧说明。
- `page_components`：媒体 Tab、功能 Tab、筛选项、表格列、按钮、导航等组件清单。
- `field_rules`：字段级规则，记录字段、子字段、展示方式、来源区域、是否复合字段、验收要点。
- `search_rules`：搜索规则，记录搜索入口、可搜索字段、匹配颗粒度、命中关系、默认口径是否生效。
- `data_scope_rules`：数据范围和统计口径，记录时间范围、数据来源、去重规则、汇总关系、待确认项。
- `confirmed_rules`：用户或产品已确认口径，必须包含确认内容、影响页面、落地位置。
- `quality_warnings`：提取质量提示，包括未访问页面、疑似漏提字段、口径冲突、交互态缺失、待确认规则。

## 版本过滤

当用户指定版本，例如 `V1.6.1`：

1. `版本` 明确等于目标版本，保留并标记 `exact`。
2. `版本` 为其他版本，排除。
3. `版本` 包含多个版本时，只有说明明确与目标版本相关才保留并标记 `mixed`。
4. 页面标题或目录命中目标版本，但单条需求是其他版本时，以单条需求版本为准排除。
5. 版本首页或侧边目录命中目标版本时，只代表页面进入候选范围；页面内每条需求仍必须按单条版本字段过滤。
6. 如果原型同一条版本内容拆出多个可独立验收点，可以在 PRD 中拆为多个功能需求，但必须保留原型来源说明，避免把“原型命中条数”和“PRD 可验收点数量”混淆。

## 交互态要求

HTML 原型常用 `hidden`、`.open`、`.modal-mask`、`.drawer-mask`、`data-tab`、`data-media` 表达交互态。提取时：

1. 静态解析隐藏弹窗、抽屉、详情容器。
2. 若需要更高可信度，使用浏览器自动化点击按钮、Tab、下拉和行内操作验证展示结果。
3. 每个交互态必须保留触发入口和结果类型。
4. 如果原型中存在明显 `新增`、`编辑`、`删除`、`详情`、`导出`、`字段设置`、`绑定`、`Tab` 入口，但未提取交互态，要在输出 `quality_warnings` 中标记。
5. 交互态中的字段不能只提取 input/select；还要提取表格表头、列表行字段、卡片字段、提示文案、底部状态、按钮禁用条件和保存结果。
6. 对于 Tab 切换后的内容，必须分别记录每个 Tab 的字段、筛选项、列表列和空态；不能只记录 Tab 名称。

## PRD 转换门禁

当 requirements.json 被整理成 PRD 时，必须执行以下自检：

1. 版本扫描清单已覆盖版本首页、侧边目录命中的目标版本页面、当前页面和关键跳转页。
2. 每条 PRD 需求都能回溯到来源页面、来源区域和原型文案或运行态字段。
3. 所有列表/表格字段均完成字段级拆解；复合字段已标记子字段和展示方式。
4. 所有搜索入口均说明可搜索字段、匹配颗粒度和命中关系；默认口径只在原型或需求说明未明确时生效。
5. 所有弹框/抽屉均提取顶部提示、Tab、筛选项、列表字段、底部状态和按钮可用条件。
6. 所有数据口径均说明时间范围、数据来源、汇总关系和去重规则；未确认项不得写入验收通过标准。
7. 用户已确认口径已同步进入“已确认口径”和对应功能规则，并移除相冲突的待确认项。

## 与下游衔接

如果用户继续要求测试点或测试用例：

1. 复杂业务先交给 `$test-object-analysis`。
2. 需要测试点时交给 `$extract-functional-test-points`。
3. 需要普通功能测试用例时交给 `$generate-functional-testcases`。
4. 不要把接口契约矩阵或 UI 自动化脚本混入本 Skill 输出。

## 完成条件

如果用户只要求提取 HTML 原型需求，完成条件是：

1. HTML 原型读取完成。
2. 版本过滤完成。
3. 版本级页面扫描清单完成，并说明未访问或访问失败页面。
4. 需求说明表、页面结构和交互态提取完成。
5. 字段级规则、搜索规则和数据口径规则完成，无法确认的内容进入待确认项。
6. `requirements.json` 生成完成。
7. 去重、结构校验、交互风险检查和 PRD 转换门禁检查完成。
