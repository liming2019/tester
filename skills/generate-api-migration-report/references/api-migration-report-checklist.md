# API 迁移报告补充检查

仅在遇到边界场景、输入缺口或人工补写时读取本文件。

## 链路类型判断

`direct`：

- 源基线直接对目标库、目标接口或目标文件。
- 没有必须单独展示的中间层快照、映射层或批次层。
- 明细页只需要说明“源到目标核验结果”。

`staged`：

- 中间层、映射层、快照层、批次层是核验证据的一部分。
- 需要分别展示“源到中间层”“中间层到目标”；全链路判断沉淀到接口概况、阶段摘要、差异样例和接口结论中，不单独渲染“总体判定依据”章节。

如果存在 `staging_layer`、`source_to_staging_summary`、`staging_to_target_summary` 或 `full_chain_consistency_summary`，默认按 `staged` 处理。

## 主报告检查

多接口主报告只能包含：

1. 顶部摘要卡片
2. 核验明细
3. 核验结论概述

主报告必须先回答：

- 顶部摘要卡片是否已经展示总体结论、测试接口数、通过接口数、阻塞接口数、失败接口数。
- 每个接口的名称、路径、范围、规则、环境、状态和详情入口是什么。
- 每个接口的核验结果概述是什么。

主报告正文不要重复渲染“执行结果概述”章节；统计信息只保留在顶部摘要卡片。
主报告不要展示字段大表、原始请求列表、批次明细、长 JSON 或所有差异样例。

## 明细报告检查

direct 明细页必须回答：

- 源基线来自哪里。
- 目标来源是什么。
- 业务键如何匹配。
- 源到目标完整性、唯一性和字段准确性是否成立。
- 源接口字段是否有未入库说明。

staged 明细页必须回答：

- 源到中间层是否正确。
- 中间层到目标是否正确。
- 全链路判断是否已在接口概况、阶段摘要、差异样例和接口结论中闭环。
- 中间层字段、映射表、批次表只作为证据，不应混入目标业务表字段清单。

## 状态口径

主报告接口级状态只展示：

- `PASS`
- `BLOCKED`
- `FAIL`

明细页字段级状态可以展示：

- `PASS`
- `WARN`
- `FAIL`
- `BLOCKED`
- `N/A`

`WARN` 和 `N/A` 必须在明细页解释，不要伪装成主报告失败，也不要直接折叠成无风险通过。

## 差异样例

有差异时优先展示 1-3 条代表样例。样例至少包含：

- 业务键
- 源标识
- 目标标识
- 差异类型或差异字段
- 预期值或源值
- 实际值或目标值
- 差异说明

staged 链路若能拿到中间层证据，还应补充中间层标识和中间层证据。

## 人工补写顺序

多接口主报告补写顺序固定为：

1. 顶部摘要卡片
2. 核验明细
3. 核验结论概述

单接口或分接口明细页补写时，先确认 `chain_type`，再按对应明细章节补齐。补写后必须重新跑输出校验。
