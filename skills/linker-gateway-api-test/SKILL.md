# Linker 网关接口测试

## 目标

使用本 Skill 执行 Linker/OpenAPI 直连网关测试，重点保证加密请求、签名鉴权、响应解密、业务断言、授权数据和证据报告可追溯。

生成或更新测试点和测试用例前，必须优先使用 `$api-test-design`；本 Skill 只补充 Linker 网关专项执行规则。
若项目 `testcases/<接口名称>测试矩阵.md` 已存在，且用户只是执行、复测或回归，必须优先复用该矩阵直接执行；只有矩阵缺失、接口文档或参数发生变化、矩阵不覆盖当前关键参数，或用户明确要求重新设计时，才重新调用 `$api-test-design` 更新矩阵。

## 必须执行的流程

1. 在项目仓库内工作时，先读取 `AGENTS.md` 和 `AGENT_RULES.md`。
2. 根据接口名称查找项目 `testcases/<接口名称>测试矩阵.md`。
3. 若矩阵存在且仍覆盖当前接口契约，执行网关测试前先读取并复用矩阵，不得重复设计用例。
4. 在进入执行前，必须先做“矩阵完整性检查”：
   - 文档中的每组独立筛选维度是否都在矩阵中单独覆盖，至少满足最小 `Each Choice`
   - 名称相似但语义不同的参数组是否拆开，例如业务日期筛选与更新时间筛选
   - 范围类参数是否覆盖开始值、结束值、开始大于结束、仅开始、仅结束、非法格式和跨度上限
   - 互斥、条件必填、分页与筛选联动、cursor 与筛选联动是否覆盖合法组合和非法组合
   - `cursor` 是否覆盖首包、仅传 cursor 续读、携带首包同值参数续读、携带不一致参数续读、重复 cursor
5. 若矩阵缺失、接口文档或参数发生变化、矩阵不覆盖当前关键参数，或矩阵完整性检查不通过，先按 `$api-test-design` 完成接口契约分析和测试点/用例设计，并更新 `testcases/<接口名称>测试矩阵.md`。
6. 执行前读取 `references/linker-gateway-contract.md`。
7. 生成报告前读取 `references/linker-evidence-report.md`。
8. 选择店铺、商家、应用、订单或售后数据前读取 `references/linker-data-setup.md`。
9. 只在测试环境或用户明确批准的非生产环境执行。
10. 按项目规范保存 Markdown、HTML、JSON 证据和报告索引。
11. 交付前必须自审最终报告。

## 执行规则

- `GW-*` 用例必须优先使用真实直连网关请求。
- 不得把调试代理成功当成直连网关业务成功。
- 若矩阵完整性检查未通过，不得直接进入执行；必须先回退到 `$api-test-design` 更新矩阵。
- 必须区分传输成功、网关鉴权成功、加解密成功和下游业务成功。
- 凭据和加解密运行环境可用时，必须执行测试侧独立解密。
- 独立解密被环境阻塞时，按影响标记 BLOCKED 或 WARN，不得静默通过。
- 执行阶段不得因测试数据不足、权限前置缺失或异常数据未准备而从矩阵中删除 `GW-*` 用例；应记录实际前置判断、数据来源和执行状态，按影响标记 PASS/FAIL/WARN/BLOCKED/待确认。
- 必须脱敏 appSecret、私钥、token、Authorization、Signature、encryptedData、密码、cookie 和生产数据。
- 每次真实网关调用必须记录原始响应 SHA256。

## 用例分类

使用以下前缀：

- `DOC-*`：接口文档发现和参数快照
- `PRE-*`：前置条件和环境检查
- `DATA-*`：测试数据发现和授权链路检查
- `GW-*`：直连网关业务测试用例
- `DB-*` 或 `DORIS-*`：数据对账检查
- `DEBUG-*`：代理或诊断用例，不得计入核心网关通过结论

核心结论必须基于 `GW-*` 和必要的数据校验，不得只根据辅助或调试用例判断。

## 汇总页统计门禁

- 主报告汇总页只展示 `GW-*` 核心直连网关用例统计、核心结论、核心 FAIL/WARN/BLOCKED 风险和明细链接。
- `DOC-*`、`PRE-*`、`DATA-*`、`DEBUG-*`、环境检查、登录、凭据、应用配置、接口文档快照和诊断项不得直接展示在汇总页用例表中，也不得计入核心接口用例通过率。
- 全量执行项统计和前置/契约/数据准备/诊断明细必须输出到独立 Markdown/HTML/JSON 明细文件，并在主报告中提供“查看全量执行明细”链接。
- 若全量执行项存在 FAIL/WARN/BLOCKED，汇总页只保留一行风险摘要和跳转链接，不展开辅助项表格。
- 报告结论必须同时说明核心接口用例结果和全量执行项是否存在影响核心结论的风险，但不得用辅助项 PASS 稀释核心接口失败率。

## 交付物要求

- 基于实际接口契约变更生成的测试点或用例清单
- 使用自动化时保留可执行脚本或执行命令记录
- Markdown 主报告
- HTML 报告
- Markdown 明细报告
- JSON 原始证据
- 项目存在报告索引时必须更新索引

## 报告门禁

最终报告必须包含：

- 请求方法
- 请求路径
- 脱敏后的请求头
- 业务明文请求体
- 加密请求体状态，且 encryptedData 脱敏
- 原始响应状态和脱敏响应体或 SHA256
- 独立解密结果
- 业务响应 code 和结构
- 断言结果
- FAIL/WARN/BLOCKED 影响说明

若本次执行前发现矩阵不完整，但用户要求先做诊断或局部验证，报告中必须明确写出：

- 本次不是完整矩阵执行
- 发现了哪些矩阵缺口
- 哪些结论只对当前诊断范围成立
- 哪些场景必须待矩阵补齐后重新执行

## 脚本复用建议

若当前项目已经存在 Linker 网关执行脚本，优先复用项目脚本，不要重复造执行器。常见目录：

- `automation/`
- `scripts/`
- `tests/`

若项目内没有执行脚本，应在项目工作区创建任务级脚本，不得把真实凭据写入 Skill 目录。
