# Linker 测试数据准备

## 配置读取

按当前项目规范读取环境配置。常见位置：

- `config/test-agent.config.local.json`
- `config/test-agent.config.example.json`
- 环境变量

不得把凭据存入 Skill 目录。

## 应用与商家

执行正向业务用例前必须确认：

- appId 存在。
- appSecret 或签名材料属于该 appId。
- 商家绑定状态有效。
- 应用具备访问目标业务范围的权限。

## 店铺授权

店铺维度接口必须：

- 优先选择当前 appId 已授权店铺。
- 使用明确授权状态，不得只按过期时间推断。
- 记录 shopId、platform、授权状态和数据来源。
- 未授权、已解绑、不存在、跨应用店铺必须作为不同边界场景。

## 业务数据

订单和售后接口必须：

- 优先选择下游数据源中存在的测试数据，例如 Doris 或业务库。
- 记录用于对账的业务唯一键。
- 正向列表场景中，仅当相同筛选条件下源数据也为空时，API 空列表才可判定通过。
- 源数据存在但 API 返回空或字段不一致时，应判定 FAIL。
- 源数据不可用时，按影响将数据正确性部分标记为 WARN 或 BLOCKED。
