# Linker 证据报告标准

## 主报告

必须包含：

- 测试类型：接口测试
- 环境和实际网关地址
- 接口路径和请求方法
- 接口契约快照来源
- 核心直连网关 `GW-*` 用例 PASS/FAIL/WARN/BLOCKED/SKIP 统计
- 基于业务场景的核心结论
- FAIL/WARN/BLOCKED 表格和影响说明
- 明细报告和 JSON 证据链接
- 全量执行明细链接

主报告不得直接展示前置、契约、数据准备或诊断项明细。若需要保留全量执行项统计，将其放入独立明细页，主报告只展示一行摘要和跳转链接。

核心接口用例表可提供用例级“查看详情”弹窗。弹窗只展示当前用例同一次请求链路证据，至少包含：

- 请求地址
- 请求头
- 请求体
- 请求加密
- 请求明文
- 响应原始报文
- 响应明文
- 断言结论

弹窗不得承载 `DOC-*`、`PRE-*`、`DATA-*`、`DEBUG-*` 全量辅助项列表；这些内容仍通过独立全量执行明细链接查看。

当核心接口用例表已提供用例级“查看详情”弹窗时，主报告不得再单独展示“接口请求参数明细”或等价的请求头、请求体、响应摘要重复表；同一请求链路证据仅保留在当前用例弹窗和独立明细报告中。

## 接口请求明细

每个真实接口请求必须包含：

- 用例编号
- 请求方法
- 请求路径
- 请求头摘要
- 业务明文请求参数
- 响应摘要
- 原始响应 SHA256

## 明细报告

每条用例必须包含：

- 测试目的
- 前置条件
- 请求 URL 和方法
- 脱敏后的请求头
- 业务明文请求体
- 加密请求体，encryptedData 必须脱敏
- 脱敏后的原始响应和 SHA256
- 独立解密结果
- 解析后的业务响应
- 断言
- 最终状态和原因

## 自审要求

最终回复前必须：

- 读取最终 HTML、Markdown、JSON 和报告索引。
- 核对统计与用例明细一致。
- 确认每个 FAIL/WARN/BLOCKED 都有影响和下一步建议。
- 确认核心用例和调试用例已分区。
- 确认主报告汇总页未直接展示 `DOC-*`、`PRE-*`、`DATA-*`、`DEBUG-*` 明细，且这些内容只能通过全量执行明细链接查看。
- 确认请求参数可见。
- 确认敏感信息已脱敏。
- 确认报告链接指向最新文件。
