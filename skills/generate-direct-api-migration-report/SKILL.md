# 直连迁移报告生成

兼容说明：新任务默认使用 `generate-api-migration-report` 并设置 `chain_type=direct`。本 Skill 暂时保留为历史 direct 专用入口；后续主报告样式和公共规则以 `generate-api-migration-report` 为准。

本 Skill 负责把“已经完成的直连迁移核验结果”整理成正式 HTML 报告，不负责重新查库、调接口或补业务规则。

## 职责边界

负责：

- 读取直连迁移核验结构化 JSON。
- 规范化源、目标、业务键、完整性、准确性、差异、阻塞和覆盖缺口。
- 生成正式中文 HTML 主报告、可选证据 HTML 和结构化 JSON 明细；结构化明细可保留定位必需的业务键和值样例，但 token、secret、私钥、签名等敏感信息必须脱敏。
- HTML 展示层必须把可中文化的结构化键名转为中文标签，避免直接展示 `migration_type`、`source_rows`、`target_batch_count` 等 snake_case 键；数据库字段名、接口路径、表名、业务键等定位性技术值可以保留原文。
- 校验报告章节、状态枚举、UTF-8、敏感信息和关键结论一致性。

不负责：

- 重新执行迁移核验。
- 将有强制中间层的链路伪装为直连链路。
- 在缺少源基线、目标来源、业务键或字段规则时强行生成 PASS 报告。

## 适用判断

使用本 Skill：

- 链路是 `源 -> 目标`。
- 没有必须展示的中间层快照、ODS、DWD、映射表阶段或多跳链路。
- 上游执行迁移测试/API 迁移核验后默认调用本 Skill 生成 HTML 报告；只有用户明确不需要测试包报告、不生成报告或不生成 HTML 时才跳过。
- 上游已经产出结构化核验结果。

不要使用本 Skill：

- 链路是 `源 -> 中间层 -> 目标`，使用 `generate-staged-api-migration-report`。
- 链路是 `源 -> raw/ods -> dwd -> api/业务层`，需要多跳报告模型。
- 当前任务仍在核验阶段，先使用 `verify-api-migration-result`。

## 设计依据

本 Skill 的报告规范来自 `references/direct-report-principles.md` 中的大厂公开实践抽象，不直接复用 staged 报告结构。

需要刷新规范或解释为什么这样设计时，读取该 reference；正常生成报告时不必读取。

## 输入要求

首选输入为 `verify-api-migration-result` 产出的结构化 JSON。直连正式报告至少需要：

- `verification_scope`：迁移对象、范围、环境、时间口径。
- `source_baseline`：源数据来源、过滤条件、抽取方式、源统计。
- `target_sources` 或 `target_source`：目标库、目标接口、目标文件等来源。
- `business_keys`：源目标匹配键、唯一性假设、歧义说明。
- `field_mapping_summary` 或 `field_assignment_rules`：字段赋值和核验规则。
- `field_accuracy_details` 必须覆盖目标表全部字段，不允许只列“看起来需要比对”的字段；接口未提供但目标表存在的字段也必须在本表中声明字段角色、预期规则和是否参与源目标值比对。
- `source_fields_not_persisted`：源接口提供但目标表未承载的字段清单；若源接口字段清单未完成结构化采集，必须显式输出 BLOCKED/WARN 说明，不能用目标表字段反推接口字段后写成 0。
- `totals_summary`：源目标总量、缺失、额外、覆盖率。
- `uniqueness_summary`：源目标唯一性和重复情况。
- `missing_in_target`、`extra_in_target`、`field_differences`：差异分组，可为空数组。
- `field_accuracy_summary` 或 `field_accuracy_details`：字段准确性核验结果。
- `coverage_gaps`：没有独立核验的范围，不能伪装成 0 差异。
- `conclusion`：`PASS`、`WARN`、`FAIL`、`BLOCKED` 及理由。
- `blocked_items`：阻塞项，可为空数组。

如果缺少关键字段：

- 缺少 `conclusion`、`source_baseline`、`target_sources/target_source` 或 `business_keys`：不得生成正式报告，只能生成草稿或要求补结构化输入。
- 缺少 `field_mapping_summary/field_assignment_rules`：字段准确性结论不得写 PASS。
- 缺少 `totals_summary`：完整性结论不得写 PASS。

## 固定执行流程

1. 读取项目级规则，尤其是报告目录、脱敏、自审和索引要求。
2. 读取结构化 JSON，先运行 `scripts/validate_direct_report.py input`。
3. 若输入校验存在关键错误，停止正式报告生成，返回错误和缺口。
4. 运行 `scripts/render_direct_migration_report.py` 生成主 HTML、结构化 JSON 明细，必要时生成证据 HTML。
5. 运行 `scripts/validate_direct_report.py output` 校验输出章节、状态、敏感信息和 UTF-8。
6. 若项目要求报告索引，更新 `reports/index.md`；索引中只挂最新正式 HTML，历史草稿不要伪装为最终版。
7. 交付前读取最终 HTML/JSON/索引做自审，确认结论和统计一致。

## 报告结构

主 HTML 固定包含以下章节：

1. 执行摘要
2. 迁移范围与口径
3. 源基线证据
4. 目标来源证据
5. 业务键与匹配策略
6. 完整性核验
7. 准确性核验
8. 接口字段未入库说明
9. 差异与阻塞
10. 覆盖缺口与风险
11. 整改建议与复跑条件
12. 附录与证据

字段章节口径：

- “准确性核验”是目标表字段声明矩阵，必须覆盖目标表全字段。
- 字段角色至少区分：源接口映射字段、系统生成字段、迁移技术字段、目标追踪/扩展字段。
- 源接口映射字段以源目标值一致性为主要核验口径；系统生成字段核验生成/写入规则；迁移技术字段仅声明批次、任务、链路追踪规则，不计作业务准确性 PASS。
- 源接口字段清单与目标表字段清单必须双向说明：目标表有但源接口未提供的字段在准确性矩阵中声明；源接口提供但未入库的字段进入“接口字段未入库说明”。
- 缺少源接口字段清单、接口实时响应或可机读官方文档字段时，“接口字段未入库说明”不得留空，应标记为 BLOCKED 或 WARN 并说明需要补充的证据。
- 字段类明细表超过一屏时必须使用固定高度滚动容器，并保持表头可见；“准确性核验”标题下不要再额外展示长段口径说明，字段口径应沉淀到表格列和明细 JSON 中。
- “执行摘要”“源基线证据”“差异与阻塞”“覆盖缺口与风险”“差异样例明细”等面向阅读的章节不得直接展示大段原始 JSON、哈希样例数组、请求/响应数组或嵌套证据对象；主报告只展示结论摘要、数量、字段级摘要、根因、影响和必要的短证据。完整可读样例、业务键哈希、值哈希、请求/响应样例必须保留在结构化 JSON 明细或证据页中，且敏感字段必须脱敏。
- 字段值不一致的字段级摘要必须对每个差异字段展示 1-3 条可读样例，格式优先为“业务键：xxx；预期值：xxx；实际值：xxx”。业务键应使用实际参与匹配的字段组合；预期值来自源侧基线或明确转换规则；实际值来自目标侧。只有核验结果没有提供原值或用户明确要求脱敏时，才回退展示业务键哈希、源/目标空值状态和值哈希，并明确样例需要补充可读证据。
- 若业务键章节声明 ODS 最新快照定位、最新行取数或多日期/多批次定位规则，字段差异样例中的“业务键”也必须展示源对象键和最新目标行定位字段，例如 `date`、`doris_update_time`、`doris_create_time`、`ods_batch_no`；不能只展示 `advertiser_id` 等单一源对象 ID。
- 差异与阻塞展示门禁：字段值不一致、源有目标无、目标有源无、BLOCKED 项不得只展示数量或笼统原因；主报告必须展示可定位样例或当前证据。字段值不一致必须有业务键、预期值、实际值；阻塞项必须有接口路径、响应码、错误信息、授权范围、缺失配置或所需证据中的至少一类实际证据。
- 业务键展示门禁：业务键必须是本次核验中实际用于源目标匹配的完整定位口径。若目标范围包含多日期、多批次、快照或重复采集记录，报告必须区分源对象键与核验匹配键，并展示日期、批次、快照时间、最新行选择规则等定位条件；不得把广告账户 ID、店铺 ID、主体 ID 等单一对象 ID 直接当完整业务键展示。

主报告要直接回答：

- 源和目标是否同范围。
- 业务键是否稳定唯一。
- 源有目标无、目标有源无、重复、字段差异分别有多少。
- 哪些字段已经验证，哪些字段只是间接证明或未覆盖。
- 结论是否受到缺少基线、权限、配置或样本限制影响。
- 需要研发修复、补数据、重跑迁移或补基线的动作是什么。

## 结论推导

统一使用：

- `PASS`：源目标完整性、唯一性、关键字段准确性均通过，且无关键覆盖缺口。
- `WARN`：无成立的核心失败，但存在非关键覆盖缺口、样本限制、只读间接证据或待确认规则。
- `FAIL`：存在源有目标无、目标有源无、重复、关键字段错误、关键文件缺失等成立错误。
- `BLOCKED`：缺少源基线、目标来源、业务键、权限、配置或关键字段规则，无法判断是否正确。

禁止：

- 把未核验维度写成 0 差异。
- 把抽样通过写成全量通过。
- 把字段规则缺失写成字段准确性 PASS。
- 因为总量一致就跳过业务键和字段准确性。

## 最终回复用户

至少输出：

1. 简短结论。
2. 正式 HTML 主报告路径。
3. 结构化 JSON 明细路径。
4. 证据 HTML 路径；若未生成，说明原因。
5. 总体状态和结论口径。
6. 总量、缺失、额外、重复、字段差异数量。
7. 已核验字段数、阻塞字段数、未覆盖字段数。
8. 是否存在必须研发修复的问题。
9. 是否存在输入不足导致的阻塞项。
