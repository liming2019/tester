# 蓝湖需求提取

这个 skill 是**蓝湖需求标准化提取器**。

职责只有一个：

- 从蓝湖原型中提取**结构化、可测试、可继续加工**的需求数据

它不是最终测试点 skill，也不是最终测试用例 skill。

## 适用场景

当用户意图是以下任一情况时触发：

- “提取蓝湖 xxx 版本的需求说明”
- “帮我把蓝湖 1.4.6 的需求整理出来”
- “从蓝湖原型中提取结构化需求”
- “先提取需求，后面还要生成测试点/测试用例”

## 不做的事

- 不直接生成最终测试点
- 不直接生成最终测试用例
- 不在本 skill 内定义测试点挂载规则
- 不在本 skill 内替下游决定字段、按钮、弹窗如何组织成测试点
- 不把 HTML 当成主输出
- 不只抓右侧“页面说明”

## 核心目标

提取并区分四类需求来源：

1. 原型正文结构化说明
2. 画布内注释
3. 画布内说明文案
4. 右侧页面说明
5. 交互态内容

最终主输出必须是**结构化 JSON**，供下游 skill 使用。

## 标准流程

1. 登录蓝湖
2. 打开目标项目与文档
3. 识别原型承载层（外层蓝湖页 / iframe / Axure 独立页）
4. 按版本词定位目标页面
5. 提取五类需求来源
6. 去重并归类
7. 生成 `requirements.json`
8. 执行结构校验与交互覆盖校验
9. 如用户需要，再补 HTML 核验报告

## 1. 登录蓝湖

优先顺序：

- 有效 cookie
- 账号密码

常见交互：

- 协议弹窗：`div.dialog div.sure`
- 登录入口：`div.loginButton.registerButton.center`
- 密码框：`input[type="password"]`

## 2. 页面定位

不要只靠截图或肉眼。

优先结合：

- 左侧页面树
- 原型数据源全文检索版本词

在正式提取前，必须先确认原型实际承载位置：

- 当前可见内容是否只是蓝湖外层壳页面
- 原型是否在 `iframe` 中，例如 `lan-mapping-iframe`
- 是否存在 Axure 独立 HTML 页、图片热点页或动态面板页

如果原型在 `iframe` 或独立 frame 中：

- 后续正文提取、注释提取、交互点击都必须在该 frame 内执行
- 不得只基于蓝湖外层 DOM、外层截图或右侧说明判定页面提取完成

常见页面树节点：

- `p.tree-name`

## 3. 四类需求来源

### A. 原型正文结构化说明

指页面中间原型画布里的正文区，通常包含：

- `版本`
- `版本内容`
- `说明`

这类内容应结构化成三列表：

- `版本`
- `版本内容`
- `说明`

### 原型正文版本过滤规则

当用户明确指定目标版本时，例如：

- `1.4.6`
- `V1.4.6`

必须在需求提取阶段先做版本过滤，再把结果传给下游。

过滤规则：

1. `版本` 明确等于目标版本
   - 保留
   - 记为 `exact`
2. `版本` 为纯其他版本，例如：
   - `V1.4.3`
   - `V1.4.2`
   - 直接排除
   - 不得进入最终 `requirements.json`
3. `版本` 为混合版本，例如：
   - `V1.4.3+V1.4.6`
   - `V1.4.6+V1.6.0`
   - 默认记为 `mixed`
   - 只有当该条说明明确与本次目标版本相关时，才允许保留
4. 如果说明内容明显是历史版本背景、默认页、旧逻辑、旧字段，而当前任务只提目标版本：
   - 即使页面本身命中了目标版本，也应从最终输出中剔除

推荐在结构化输出中增加字段：

- `version_match`
  - `exact`
  - `mixed`
  - `excluded`
- `included_in_target_version`
  - `true`
  - `false`

默认原则：

- 不属于目标版本的内容，提取阶段就过滤掉
- 不要把版本清洗的责任留给测试点提取 skill

### B. 画布内注释

指 Axure 注释点，如：

- `1`
- `A1`

不要只靠点黄标，优先直接读运行时数据源：

- `window.lanhu_pageDataJsObj.notesData.widgetNotes`
- `window.lanhu_pageDataJsObj.notesData.masterNotes`
- `window.lanhu_g.pageBindElData.annotations`

标准字段：

- `注释编号`
- `标签`
- `说明`

### C. 画布内说明文案

指直接写在画布里的说明文字，不属于注释点，也不属于右侧说明。

示例：

- `该分类下的视频累计消耗到此值后将会被定义为爆品`

标准字段：

- `位置`
- `关联字段`
- `文案`

### D. 右侧页面说明

指蓝湖右侧“评论与页面说明”区域。

常见容器：

- `.comment_box.doc-comment-list`
- `.element_note_item`

标准字段：

- `序号`
- `元素/字段`
- `说明`

注意：

- `元素/字段` 优先输出业务字段名
- 不要直接输出 `(下拉列表)`、`(文本框)` 这类通用控件名
- 只有确实找不到业务语义时，才退回通用控件名

### E. 交互态内容

指原型中通过点击、悬停、切换 Tab、选择下拉、点击按钮或操作项后才出现的内容，例如：

- 点击“新增爆品”后显示“新增爆品设置”弹窗
- 点击“编辑”后显示编辑弹窗
- 点击列表操作项后进入二级页、抽屉或浮层
- Tab 切换后出现另一组列表、筛选项或说明

交互态不是截图之外的可选补充，而是需求提取必须覆盖的内容。只要页面存在可触发入口，就应尝试触发并记录触发后的状态。

这是强制项，不是建议项。

如果页面存在以下任一入口：

- `新增`
- `编辑`
- `删除`
- `详情`
- `导出`
- `操作`
- `Tab`
- 下拉切换
- 热区 / hotspot

则不得跳过交互态提取，也不得在 `interaction_states` 为空的情况下判定该页面完成。

提取方式：

- 优先读取 Axure 运行时交互配置、动态面板状态、widget 事件和页面绑定数据
- 再用浏览器自动化点击页面上的业务入口验证实际展示结果
- 对每个明显业务按钮、链接、操作项、Tab、下拉触发入口，至少尝试一次有效触发
- 触发后截图并提取弹窗、抽屉、二级页、浮层或新状态中的标题、字段、按钮、说明文案和注释
- 如果点击没有产生可见变化，也应记录为 `no_visible_change`，但不要把它当作需求输出给下游，除非用户要求排查交互

标准字段：

- `trigger`
  - 触发入口文本，例如 `新增爆品`
- `trigger_type`
  - `button`
  - `link`
  - `table_action`
  - `tab`
  - `dropdown`
  - `hotspot`
- `interaction`
  - `click`
  - `hover`
  - `switch`
  - `select`
- `result_type`
  - `modal`
  - `drawer`
  - `popover`
  - `panel_state`
  - `secondary_page`
  - `no_visible_change`
- `title`
  - 弹窗、抽屉、二级页或状态标题
- `fields`
  - 字段数组，字段包含 `name`、`type`、`required`、`default`、`options`、`description`
- `actions`
  - 操作数组，例如 `确定`、`取消`、`关闭`
- `notes`
  - 当前交互态下的说明、注释或可见提示文案
- `screenshot`
  - 当前交互态截图路径

归类规则：

- 交互态内容必须保留触发入口信息
- 交互态内容必须能追溯到原始页面和触发关系
- 若同一个交互态已经出现在独立页面树节点中，优先保留入口关系，并记录 `source_page`
- 本 skill 只负责把交互事实写入结构化结果，不负责把这些事实挂载成测试点树

失败判定：

- 页面截图中可见明显交互入口，但 `interaction_states` 为空
- 表格管理页存在操作列，但未覆盖新增/编辑/详情/删除等可见入口
- 页面存在 Tab、下拉、二级页或弹窗入口，但未尝试触发
- 只提取了右侧页面说明或静态正文，未验证交互态

出现以上任一情况，都不得将该页面标记为“提取完成”。

## 4. 去重规则

- 同一条内容如果属于“画布内注释”，不要再在“右侧页面说明”重复展示
- 画布内直接说明文案不要伪装成注释
- 空区块不渲染
- 不要输出“无内容占位行”，除非用户明确要求

## 5. 主输出格式

主输出固定为：

- `requirements.json`

推荐顶层结构：

```json
{
  "source": {
    "platform": "lanhu",
    "domain": "ysp",
    "project_name": "云视频",
    "version": "1.4.6",
    "doc_name": "云视频_最新"
  },
  "pages": []
}
```

每个页面对象至少包含：

- `page_name`
- `page_url`
- `page_group`
- `page_module`
- `screenshot`
- `prototype_structured`
- `canvas_annotations`
- `canvas_text_notes`
- `interaction_states`
- `right_panel_notes`
- `raw_prototype_text`

字段约束：

- `prototype_structured`：数组，元素字段固定为
  - `版本`
  - `版本内容`
  - `说明`
- `canvas_annotations`：数组，元素字段固定为
  - `注释编号`
  - `标签`
  - `说明`
- `canvas_text_notes`：数组，元素字段固定为
  - `位置`
  - `关联字段`
  - `文案`
- `interaction_states`：数组，元素字段固定为
  - `trigger`
  - `trigger_type`
  - `interaction`
  - `result_type`
  - `title`
  - `fields`
  - `actions`
  - `notes`
  - `screenshot`
- `right_panel_notes`：数组，元素字段固定为
  - `序号`
  - `元素/字段`
  - `说明`

## 6. 辅助输出

只有在用户需要人工核验时，再补：

- `requirements.html`
- `prototype_structured.html`
- 页面截图

HTML 每页固定顺序：

1. 页面标题
2. 页面链接
3. 原型截图
4. 原型正文结构化说明
5. 画布内注释
6. 画布内说明文案
7. 交互态内容
8. 右侧页面说明提取

## 6.1 输出前校验

在生成最终 `requirements.json` 前，至少执行以下检查：

1. 是否识别并进入了真实原型承载层
2. 页面截图中的正文、表格、按钮、弹窗是否与结构化结果一致
3. 若页面存在明显交互入口，`interaction_states` 是否非空
4. 若页面命名为混合版本，例如 `V1.4.3+V1.4.6`，是否显式标记 `version_match`
5. 是否存在“截图里有按钮、JSON 里无交互项”的情况

如果校验未通过：

- 不要直接交付最终需求结果
- 应继续补抓交互态、frame 内容或版本过滤结果

建议为关键交互态保留证据：

- 点击前截图
- 点击后截图
- 弹窗标题
- 字段列表
- 按钮列表

自动化脚本要求：

- 中文选择器优先使用 UTF-8 或 Unicode 转义
- 不要依赖终端默认编码
- 关键按钮文本最好同时保留文本定位和结构定位两套方案

## 7. 文件命名规则

根据业务域确定前缀：

- 云视频：`ysp_版本号`
- 货军师：`hjs_版本号`

示例：

- `ysp_1.4.6_requirements.json`
- `ysp_1.4.6_requirements.html`
- `ysp_1.4.6_prototype_structured.html`

截图建议命名：

- `前缀_页面名.png`

## 8. 完成条件

如果用户只说“提取需求说明”，完成条件是：

1. 页面定位完成
2. 真实原型承载层确认完成
3. 五类需求来源提取完成
4. 若页面存在可见交互入口，则交互态提取完成
5. `requirements.json` 生成完成
6. 通过结构校验与交互覆盖校验

如果用户后续还要测试点或测试用例，不在本 skill 内完成，而是交给上层编排 skill。

## 下游边界

- 下游若要生成测试点，应直接消费 `requirements.json` 或其等价结构化字段
- `canvas_annotations`、`canvas_text_notes`、`interaction_states` 如何挂到字段、操作项或模块下，由 `$extract-functional-test-points` 决定
- 是否需要先做复杂业务对象分析，由 `$lanhu-to-testcase` 或调用方决定
- 本 skill 只保证“事实完整、来源清晰、结构可消费”，不保证“已经组织成测试点评审树”
